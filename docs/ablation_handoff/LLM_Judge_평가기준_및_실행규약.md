# 금융 Ablation의 LLM Judge 평가 기준 및 실행 규약

> 상태: 이 문서는 2026-09-18의 이전 분석단계 Judge 설계 기록이다.
> 최종 보고서 평가는 `run_config/FINAL_REPORT_LLM_JUDGE.md`와
> `run_config/final_report_llm_judge.py`의 360회 FinRPT식 규약을 사용한다.

작성일: 2026-09-18. 현재 5개 기업 × 5개 조건 × 3회 생성 결과를 대상으로 한다. 이 문서는 평가 설계이며, Judge 호출·사람 검증·평가 점수 산출은 아직 실행하지 않았다.

확정 설정: `gpt-5.6-terra`, `reasoning.effort=low`. 평가 단위별 세 기준을 한 요청에서 개별 판정한다. 본 평가 150회와 사전 선정한 순서 교환 검사 45회, 총 195회를 계획한다. 기존 데이터·월별 요약·생성 결과를 재사용하며, 이 문서 수정으로 유료 호출을 시작하지 않는다.

## 1. 평가의 세 축

1. **공통 근거 기반 A/B 품질 비교:** 동일 원천 자료를 기준으로 어느 분석이 기업 상황을 더 타당하게 설명하는지 평가한다.
2. **실제 입력에 대한 근거 충실도:** 각 후보의 주장이 그 후보에게 실제 제공된 자료로 뒷받침되는지 독립 검사한다.
3. **순서 교환 일관성:** 사전에 층화 추출한 30% 표본에서 A/B 순서를 바꾼 두 판정이 일치하는지 기록한다.

공통 근거에 있는 사실이 후보의 실제 입력에는 없을 수 있다. 따라서 첫 번째 평가에서 지지되는 주장이라도 두 번째 평가에서는 입력 근거가 없을 수 있다. 세 축을 하나의 종합 점수로 합치지 않는다.

## 2. 조건별 평가 단위

| 비교 | 평가 단위 | 해석 |
|---|---|---|
| Full vs No-subdata | Financial / News / Market 각각 | 하위 분석 보조자료의 기여 |
| Full vs Random news | News | 뉴스 선정 변경의 주 효과 |
| Full vs Random news | Financial / Market 각각 | 달라진 뉴스 보조자료의 전파 효과 |
| Full vs No-peer | Strategy / 최종 보고서 각각 | 비교기업 정보의 기여 |
| Full vs One-team | Full의 세 도메인 분석 묶음 vs One-team 통합 분석 | 역할 분리와 통합 분석 구조의 차이 |
| Full vs One-team | 최종 보고서 | 구조 차이가 최종 결과에 미치는 영향 |

동일 기업·동일 회차끼리 비교한다. 가장 좋은 회차를 골라 비교하거나 서로 다른 회차를 짝짓지 않는다. No-peer의 하위 분석은 같은 회차 Full과 동일하므로 평가하지 않는다. One-team 전체를 Full의 한 도메인과 비교하지 않는다.

위 표는 평가 단위 기준으로 3 + 3 + 2 + 2 = 10개다. 각 단위에 기준 세 개를 적용하므로 회차·기업당 기준 적용은 30건이다. 질문 문장은 Financial / News / Market / 통합 분석 / Strategy / 보고서의 여섯 묶음, 총 18개를 재사용한다. 30개가 모두 서로 다른 질문이라는 뜻은 아니다.

Full과 Random 비교는 DART 기업 필터와 공시 관련성 선정을 함께 제거한 효과다. 순위 알고리즘 하나만의 효과라고 해석하지 않는다. One-team도 호출 수와 정보 접근 문맥이 달라지는 구조 비교임을 유지한다.

## 3. 공통 평가 자료 구성

### 자료 선택 원칙

기업·평가 단위별 자료를 후보 분석의 우열을 보기 전에 고정한다. 같은 단위의 모든 비교와 순서 교환에서 동일한 자료를 사용한다.

- 재무: 기간·공개일·연결/별도 기준과 함께 주요 재무 추세, 사업별 매출, 필요한 원천 수치를 제공한다.
- 시장: 기간별 절대·시장 대비 수익률, 월별 흐름, 추세·변동성·거래량 지표와 관측 시점을 제공한다.
- 뉴스: Full 선정 기사와 Random 선정 기사의 합집합을 사용한다. 날짜·제목·원래 제공된 스니펫·사건 진행 내역을 보존한다.
- 비교기업: Strategy와 최종 보고서 평가에는 동일 기준의 비교기업 재무·시장 자료와 해당 기업 뉴스 합집합을 제공한다. 생성된 비교기업 분석문을 사실의 정답으로 사용하지 않는다.

Financial / News / Market과 대상기업 통합 분석의 공통 자료에는 대상기업의 재무·시장·뉴스를 제공한다. Strategy와 최종 보고서는 비교기업 원천 자료도 포함한다. No-peer의 Judge에도 같은 비교기업 자료를 제공하되, 실제 입력 충실도 검사에는 No-peer가 실제 받은 자료만 사용한다.

### 중복과 ID

Full·Random 간 같은 원문과 동일 스니펫은 한 번만 제공한다. 같은 URL이라도 제공된 스니펫이 다르면 차이를 보존한다. 제목이 비슷하거나 같은 사건을 다룬다는 이유만으로 후속 보도·서로 다른 수치·다른 시점을 지우지 않는다.

평가용 ID는 `EV0001`처럼 조건을 드러내지 않게 새로 부여한다. 원래 기사·근거 ID와의 대응표, 원천 경로와 해시는 Judge에게 보여주지 않는 감사 파일로 저장한다. 후보 분석의 인용 ID도 대응표로 치환하며 인용하지 않은 근거를 임의로 덧붙이지 않는다.

### 분량과 자료 수준

생성된 월별 뉴스 요약이나 Strategy 해석을 공통 원자료의 대체물로 삼지 않는다. 월별 요약은 실제 입력 충실도 검사에서는 그 후보가 받은 입력으로 취급한다.

전체 일별 시장 데이터와 공시 전문을 모두 넣을 필요는 없지만 판정에 필요한 수치·기간·정의는 유지한다. 예비 검토에서 입력량을 확인하고 자료 범위를 고정한다. 후보에 유리한 자료만 남기거나, 문맥 한도 때문에 자료를 조용히 잘라 평가하지 않는다. 자료 묶음이 판정에 불충분하면 보완 후 동일 설정으로 다시 준비하거나 판단 불가로 기록한다.

뉴스 합집합은 두 조건에 제공된 기사 범위의 공통 근거다. 전체 뉴스에서 중요 사건을 얼마나 포착했는지 측정하는 정답 목록이 아니다. 중요 사건 누락률은 평가하지 않는다.

## 4. 모든 품질 평가에 적용하는 공통 지침

Judge는 조건명·생성 모델·선정 점수·기존 BERTScore를 보지 않는다. 후보는 A와 B로 표시한다. 제공 자료 외의 기업 지식, 기준일 이후 사실과 실제 미래 수익률을 판정 근거로 사용하지 않는다.

한 요청에는 해당 평가 단위의 기준 세 개를 넣고, 기준별 판정·이유·근거 ID를 별도 필드로 받는다. 각 기준은 하나의 평가 질문을 유지한다. 다른 기준에서 잘 썼다는 이유로 이번 기준의 결함을 상쇄하지 않는다. 설명 길이, 인용 개수, 여러 도메인 언급 자체, 단정적인 어투에 보상을 주지 않는다. 같은 호출의 세 판정이 통계적·인지적으로 독립이라고 가정하지 않으며, 이를 '기준별 개별 판정'으로 기술한다.

관련 자료를 적절히 연결했을 때만 그 연결의 가치를 인정한다. 동시 발생이나 방향 일치를 인과관계의 증명으로 취급하지 않는다. 원인이나 전망을 확인할 수 없다고 적절히 유보한 분석은 근거 없는 상세 설명보다 나을 수 있다.

`Tie`는 이번 기준에서 실질적 우열이 없을 때 사용한다. `Cannot determine`은 공통 자료의 부족·충돌 등으로 우열을 판단할 수 없을 때 사용한다. 두 후보 모두 부실해도 동일하게 부실하다고 판단할 수 있다면 동률이다. 한쪽 분석에 근거가 없고 다른 쪽은 타당하다면 자동으로 판단 불가 처리하지 않는다.

미래 전망은 실제로 맞았는지가 아니라 제공 근거로 어느 정도 정당화되는지 평가한다. 미래 수익률이나 숨겨진 정답 투자의견을 요구하지 않는다.

## 5. 확정할 품질 평가 문장

아래의 질문과 설명을 각각 하나의 평가 기준으로 사용한다. 모든 기준의 답변 형식은 `A / B / Tie / Cannot determine`다.

### Financial

| ID | 질문 | 판정 범위 |
|---|---|---|
| F1 | **공통 근거에 비추어, 어느 분석이 관측된 수익성 변화에 더 타당한 설명을 제시하는가?** | 영업이익·이익률·비용 구조와 필요한 뉴스 문맥을 검토한다. 원인이 확인되지 않으면 유보를 인정한다. |
| F2 | **공통 근거에 비추어, 어느 분석이 현금흐름이 보여주는 이익의 질을 더 타당하게 해석하는가?** | 이익과 영업현금흐름 등의 관계에 한정한다. 자료에 없는 현금흐름 악화 원인을 꾸며내지 않는다. |
| F3 | **공통 근거에 비추어, 어느 분석이 기업의 재무 부담 수준을 더 타당하게 판단하는가?** | 부채·유동성·자본 및 현금 창출 여력에 근거한 부담 판단을 본다. 단순 지표 나열이나 무조건적 위험 강조에 보상을 주지 않는다. |

### News

| ID | 질문 | 판정 범위 |
|---|---|---|
| N1 | **공통 근거에 비추어, 어느 분석이 뉴스에서 확인되는 사건의 대상기업 사업상 의미를 더 타당하게 해석하는가?** | 계열사·지주회사·산업 일반 소식을 대상기업 자체 실적처럼 해석하지 않는다. 기사 수나 사건 수 자체는 평가하지 않는다. |
| N2 | **공통 근거에 비추어, 어느 분석이 뉴스 사건의 재무적 영향을 더 타당하게 설명하는가?** | 확인된 영향과 가능성을 구분한다. 재무 효과가 아직 확인되지 않았다면 적절한 유보를 인정한다. |
| N3 | **공통 근거에 비추어, 어느 분석이 뉴스와 주가 반응의 관계를 더 타당하게 설명하는가?** | 기사 시점과 시장 관측 시점이 맞는지 확인한다. 가격 움직임만으로 특정 뉴스가 원인이라고 단정하지 않는다. |

### Market

| ID | 질문 | 판정 범위 |
|---|---|---|
| M1 | **공통 근거에 비추어, 어느 분석이 대상기업의 시장 대비 성과를 더 타당하게 해석하는가?** | 동일 기간의 절대수익률과 KOSPI 대비 성과를 구분한다. 서로 다른 기간의 지표를 같은 성과로 취급하지 않는다. |
| M2 | **공통 근거에 비추어, 어느 분석이 관측된 가격 추세의 지속 가능성을 더 타당하게 판단하는가?** | 가격 추세·모멘텀·거래량 등이 보여주는 지속 가능성 판단을 본다. 과거 지표를 확정적 미래 예측으로 바꾸지 않는다. |
| M3 | **공통 근거에 비추어, 어느 분석이 가격 흐름과 기업 상황의 관계를 더 타당하게 해석하는가?** | 뉴스·재무 자료와 시장 흐름을 연결한 설명의 근거를 평가한다. 보조자료가 시장 관측값을 대체하지 않는다. |

### Full 세 도메인 묶음 vs One-team 통합 분석

| ID | 질문 | 판정 범위 |
|---|---|---|
| U1 | **공통 근거에 비추어, 어느 분석이 대상기업 상황을 더 타당하게 종합하는가?** | Full의 세 결과 전체와 One-team의 통합 결과를 각각 하나의 후보로 본다. Full에 없는 추가 종합문을 평가 준비자가 작성하지 않는다. |
| U2 | **공통 근거에 비추어, 어느 분석이 자료 간 상충하는 신호를 더 타당하게 해석하는가?** | 예를 들어 실적 개선과 가격 부진이 함께 관측될 때 설명이 자료로 지지되는지 평가한다. 상충 신호가 없으면 억지로 만들지 않는다. |
| U3 | **공통 근거에 비추어, 어느 분석이 대상기업 전망을 더 타당하게 설명하는가?** | 전망을 지지하는 관측과 필요한 조건의 관계를 평가한다. 강제적인 매수·중립·매도 선택은 요구하지 않는다. |

### Strategy

| ID | 질문 | 판정 범위 |
|---|---|---|
| S1 | **공통 근거에 비추어, 어느 분석이 최종 12개월 의견을 더 타당하게 뒷받침하는가?** | 선택한 의견과 주요 근거의 관계를 본다. 특정 의견이나 상승여력 수치의 제시 자체에 보상을 주지 않는다. |
| S2 | **공통 근거에 비추어, 어느 분석이 최종 의견에 반대되는 근거의 중요도를 더 타당하게 판단하는가?** | 반대 근거를 나열한 개수보다 왜 최종 의견을 바꾸거나 바꾸지 않는지 설명한 타당성을 본다. |
| S3 | **공통 근거에 비추어, 어느 분석이 대상기업의 상대적 위치를 최종 판단에 더 타당하게 반영하는가?** | 비교기업을 언급했다는 이유로 보상을 주지 않는다. 비교 기준의 차이가 대상기업 판단에 실제로 어떤 의미가 있는지 본다. |

### 최종 보고서

| ID | 질문 | 판정 범위 |
|---|---|---|
| R1 | **공통 근거에 비추어, 어느 보고서가 대상기업에 대한 핵심 투자 논지를 더 타당하게 제시하는가?** | 주요 근거가 투자 논지를 지지하는지 평가한다. 문장 유창함이나 보고서 길이는 기준이 아니다. |
| R2 | **공통 근거에 비추어, 어느 보고서가 제시한 투자 논지의 취약점을 더 타당하게 설명하는가?** | 일반적 주의문 대신 해당 기업 판단이 흔들릴 수 있는 근거와 연결되는지를 본다. 불확실성이 크다는 표현 자체에 보상을 주지 않는다. |
| R3 | **공통 근거에 비추어, 어느 보고서가 향후 12개월 판단을 좌우할 조건을 더 타당하게 제시하는가?** | 확인된 사실과 전망 조건을 구분해 판단한다. 향후 자동 모니터링이 실제 구현되어 있다고 가정하지 않는다. |

최종 보고서 후보는 서술 본문과 Writer가 작성한 차트 해석이다. 차트 해석을 포함한다면 모든 후보에 동일한 추출 정책을 적용한다. 고정 고지문·레이아웃·이미지 품질은 평가하지 않는다. BERTScore의 기존 서술 본문 추출 범위와 이 품질 평가의 범위는 명세에 각각 기록한다.

## 6. 공통 근거 A/B Judge 입력 및 출력

```text
[대상과 분석 시점]
기업명, 기준일, 자료 이용 가능 시점, 평가 단위

[공통 평가 근거]
EV0001: 원천 수치·문장, 기간·날짜, 기업, 연결/별도 기준
EV0002: ...

[분석 A]
저장된 후보 분석의 관련 내용과 치환한 근거 ID

[분석 B]
저장된 후보 분석의 관련 내용과 치환한 근거 ID

[평가 기준 세 개]
해당 평가 단위의 질문 세 개와 각 판정 범위

[출력]
각 기준 ID별로 다음 필드를 따로 반환한다.
  판정: A / B / Tie / Cannot determine
  이유: 해당 기준에서의 우열 또는 판단 불가 이유
  공통 근거 ID: 판정을 뒷받침한다고 기록한 EV ID
  후보 문장: 판정과 관련된 A/B의 짧은 원문 구절
```

공통 자료의 ID가 존재하는지 검사하고, 인용한 근거가 실제 이유를 지지하는지는 사람 검토에서 확인한다. ID 출력은 Judge가 제시한 인용 기록이다. 내부 추론에서 그 근거를 인과적으로 사용했다는 증거로 취급하지 않는다.

## 7. 실제 입력 근거 충실도 검사

이 검사는 A/B 우열을 묻지 않고 후보 하나씩 수행한다. 평가 입력은 후보의 실제 LLM 입력과 후보 분석이다. No-subdata에 공통 평가 자료의 뉴스·시장 내용을 추가하거나, Writer에게 제공되지 않은 공시 전문을 추가하지 않는다.

전체 산출물 전수 검사가 아니라 별도 층화 표본검사로 수행한다. 기업·조건·산출물 종류를 고려해 결과를 보기 전에 표본과 수량을 정하고 별도로 예산을 산정한다. 의심 사례만 추가 검사한 결과는 무작위 표본 결과와 분리한다. 이 검사와 예비실험은 본 평가 195회에 포함하지 않는다. 숫자·기간·ID 존재 여부의 코드 점검은 보조 진단이며 의미적 근거 충실도 판정을 대체하지 않는다.

시장 분석은 저장된 원자료·입력 구성 코드로 실제 모델 입력을 재구성할 수 있는지 확인하고 해시 또는 원래 입력 구성과 대조한다. 사후에 늘어난 자료를 실제 입력으로 간주하지 않는다. 입력을 충분히 복원할 수 없다면 검증 불가로 기록한다.

**검사 질문:** “이 주장은 후보에게 실제 제공된 입력으로 뒷받침되는가?”

| 분류 | 정의 |
|---|---|
| 입력으로 지지됨 | 직접 관측 사실, 확인 가능한 계산, 입력에 근거한 적절히 제한된 해석 |
| 입력과 모순됨 | 수치·방향·기간·기업 등이 입력과 충돌함 |
| 입력 근거 없음 | 필요한 사실 또는 인과 근거가 입력에 없는데 이를 사실로 주장함 |
| 검증 불가 | 입력 복원·원천 문맥 등이 부족해 지지 여부를 판단할 수 없음 |

주장별로 후보 원문 구절, 분류 이유, 실제 입력 근거 ID를 기록한다. 보수적인 유보와 조건부 전망을 사실 주장과 구분한다. 합리적인 해석이 원문에 그대로 쓰여 있지 않다는 이유만으로 입력 근거 없음으로 분류하지 않는다.

분류를 완전한 외부 사실의 진위 판정이나 의도적 조작의 증거로 해석하지 않는다. 장황함 때문에 주장 수가 늘 수 있으므로 고유 주장 단위와 중복 처리 원칙을 고정하고, 지지 비율뿐 아니라 모순·근거 없음·검증 불가의 개수와 비율을 함께 보고한다. 공통 근거 품질 판정에 이 검사를 합쳐 새로운 종합 점수를 만들지 않는다.

## 8. 후보 위치 무작위화와 순서 교환 검사

본 평가 150쌍은 각각 한 요청에서 세 기준을 판정한다. 최초 Full의 A/B 위치는 비교 단위별로 가능한 한 균형 있게 무작위 배치한다. 단위별 15쌍은 7/8 배치로 만들고, 전체는 75/75가 되도록 큰 쪽의 방향을 균형 배정한다. 후보 위치는 같은 요청의 세 기준에 동일하게 적용한다.

본 평가 결과를 보기 전에 150쌍 중 45쌍을 기업·비교 단위·회차를 고려해 층화 추출한다. 평가 기준 하나씩 표본을 뽑는 것이 아니라 후보 쌍을 뽑아 그 쌍의 세 기준 모두를 검사한다. 고정 난수 시드, 후보 위치표, 검사 대상표와 자료 해시를 저장한 뒤 호출한다. 단위별 검사 수는 4~5쌍으로 배분하고 기업·회차의 편중을 줄인다. 정확한 층별 수량과 선정 결과는 실행 명세에 남긴다.

검사 대상에만 A/B 위치를 뒤집은 추가 요청을 수행한다. 두 번째 요청에 첫 판정 결과를 제공하지 않는다. 모델·자료 내용 및 배열·기준 순서·출력 설정은 같게 유지하고 후보 위치만 바꾼다. 각 요청은 별도 문맥에서 실행하며 이전 판정이나 내부 추론을 이어받지 않는다.

본 평가 판정은 조건으로 복원해 `Full 승 / Full 패 / 동률 / 판단 불가`로 기록한다. 표본의 추가 판정으로 최초 판정을 교체하거나, 검사한 사례에만 이중 판정의 엄격한 집계를 적용해 전체 본 평가에 섞지 않는다.

순서 교환 검사는 기준별로 별도 기록한다. 두 판정 모두 판단 가능한 경우 조건으로 복원한 값이 같으면 '일치', 다르면 '불일치'다. 승/동률과 승/패 모두 불일치이며 서로 구분해 판정 전이표에 남긴다. 하나라도 `Cannot determine`이면 판단 불가 포함 사례로 별도 기록하고, 분석 우열에 대한 일치율 분모에서는 제외한다. 두 번 모두 판단 불가인 경우도 우열 판단의 안정성으로 계산하지 않는다.

총 45쌍 × 세 기준 = 135건의 기준별 순서 비교를 얻지만 같은 쌍의 세 판정을 독립 표본으로 가정하지 않는다. 전체 150쌍의 일치 여부가 검증됐다고 주장하지 않는다. 불일치 판정을 원하는 결론이 나올 때까지 재호출하지 않는다. 오류·미완료는 승/패/동률/판단 불가로 임의 변환하지 않고 별도로 남긴다.

## 9. 집계와 사람 검증

비교 조건·평가 단위·평가 기준별로 본 평가의 승/패/동률/판단 불가를 공개한다. 네 범주의 비율 분모는 해당 기준의 본 평가가 완료된 모든 쌍이다. 오류·미완료 수와 계획된 쌍 수도 함께 표시한다. 승/패 사례만의 승률을 제시한다면 이를 별도 지표로 표시하고 전체 쌍의 분포를 반드시 함께 제시한다. 순서 교환 표본의 일치율·불일치 수·판단 불가 포함 수·오류 수는 별도 표로 보고한다.

한 비교 단위·한 기준은 5개 기업 × 3회 = 15쌍이다. 기업별 3쌍과 전체 15쌍을 구분해 기록한다. 기사나 주장 개수를 독립 기업 표본처럼 세지 않는다. A/B 순서 교환 2회도 독립 생성 회차 2개로 세지 않는다.

표준 실행 범위는 10개 비교 단위 × 기업 5개 × 회차 3개 = 150개 후보 쌍이다. 한 요청에 세 기준을 묶어 본 평가 요청은 150회, 기준별 판정은 450건이다. 30% 표본의 순서 교환 45회를 더해 **총 195회 Judge 요청**으로 계획한다. 실제 입력 충실도 검사와 예비실험은 별도 요청이며 이 수량에 포함하지 않는다. 기존 고정 데이터와 생성 결과를 재사용하고 뉴스 요약·분석 보고서를 재생성하지 않는다.

모델과 추론 수준은 `gpt-5.6-terra`, `low`로 고정한다. Batch API를 우선 사용하되 계정 지원·대기열 한도를 확인한다. 지원되지 않으면 Standard로 자동 전환하지 않고 비용 차이를 보고한 뒤 실행 방향을 정한다. 도구 검색이나 외부 사실 조회 없이 제공된 자료만으로 판정한다. 기준일 이후 지식을 쓰지 말라는 지침이 지식 누출을 완전히 제거한다고 주장하지 않는다.

전체 유료 실행 전에 최종 150개 본 평가 프롬프트의 토큰 수를 측정해 `min / median / mean / p90 / p95 / max / 272,000 초과 개수`를 저장한다. 설치된 토크나이저가 모델을 직접 지원하지 않으면 대체 인코딩과 근사치임을 명시한다. 기존 탐색적 측정은 평균 약 102,651, 최대 약 179,099토큰이었으나 최종 프롬프트 측정 결과로 대체해야 한다. 뉴스 근거를 줄여야 한다면 특정 후보에 유리하게 조정하지 않고 공통 정책을 사전에 고정한다.

10~20쌍의 소규모 예비 평가로 JSON 형식 준수, 판단 불가의 사유, 근거 ID 존재·적절성, 실제 출력량과 추론 토큰 사용량을 확인한다. 예비 표본은 판정을 보기 전에 기업·조건·평가 단위를 고려해 정하며 Full 승리 사례만 고르지 않는다. 사람이 같은 공통 자료와 같은 기준으로 독립 평가하고, Judge와의 일치율·불일치 사례를 확인한다. 두 명 이상이 참여할 수 있으면 사람 간 일치도도 기록한다. 일부 표본에서 기준별 별도 요청과 묶음 요청을 대조할 경우 추가 호출·예산을 별도로 명시한다.

기준을 수정한다면 해당 예비 결과는 최종 고정 기준의 점수와 섞지 않는다. 예비 결과의 본 평가 포함 여부는 사전에 명시하며, 기본적으로 별도 검사 결과로 둔다. 한국어 금융 판단에 대한 사람 검증 전에는 기존 일반 문장 평가 연구의 일치율을 우리 평가의 신뢰도로 인용하지 않는다. 생성 모델과 Judge 모델이 다르더라도 편향이 없다고 가정하지 않는다.

### 비용 산정과 기록

2026-09-18 [공식 Terra 모델 문서](https://developers.openai.com/api/docs/models/gpt-5.6-terra)에 따른 100만 토큰당 Standard 요금은 입력 $2, 캐시 입력 $0.20, 출력 $12다. 입력 272,000토큰을 넘으면 요청 전체에 입력 2배·출력 1.5배 요금이 적용된다. 캐시 쓰기는 비캐시 입력 단가의 1.25배로 명시되어 있으므로 적용 여부와 실제 쓰기 사용량을 별도 확인한다. [Batch 안내](https://developers.openai.com/api/docs/guides/batch)는 동기 API 대비 50% 할인을 명시한다.

이전 평균 입력량과 요청당 가시 출력 600~1,200토큰으로 계산하면 195회는 Standard 약 $41~43, Batch 약 $21이다. 이는 최종 비용이나 확정 상한이 아니다. 추론 토큰·캐시 쓰기·예비실험·충실도 검사·재시도·장문 요금은 이 예시에 포함하지 않았다. 캐시 적중을 기본 예산에 가정하지 않는다. [추론 모델 안내](https://developers.openai.com/api/docs/guides/reasoning)에 따라 추론 토큰도 출력 단가로 과금되므로 예비 호출 사용량으로 최종 실행 예산을 재산정한다.

195회에서 요청당 평균 추론 1,000토큰이 추가되면 Standard 약 $2.34, Batch 약 $1.17이 더해진다. 이는 산식 예시이며 `low`의 실제 사용량을 보장하지 않는다. 토큰·비용 계산에서는 API의 전체 출력 토큰에 이미 포함된 추론 토큰을 다시 더하지 않는다. 원본 사용량, 캐시·추론 세부 사용량, 적용 요금과 실패 요청 비용을 감사 파일에 보존한다. 과도한 출력 상한으로 JSON이 잘리지 않도록 예비 결과로 설정하고, 잘린 출력을 임의 판정이나 무제한 재호출로 처리하지 않는다.

## 10. 선행 연구와 방법 설명

- [G-Eval, EMNLP 2023](https://aclanthology.org/2023.emnlp-main.153/): 원문을 활용한 생성 문장 품질·일관성 평가의 선례.
- [RAGAS, EACL 2024](https://aclanthology.org/2024.eacl-demo.16/): 입력 문맥에 대한 주장별 근거 충실도 평가의 선례. 원논문은 사람의 쌍별 선호와 자동 평가 결과를 대조하고 GPT Ranking도 비교 방법으로 사용했다. 핵심 방법을 우리의 직접 A/B 금융 평가와 동일시하지 않는다.
- [MT-Bench 연구, NeurIPS 2023](https://arxiv.org/abs/2306.05685): 직접 A/B 비교와 위치·분량·자기 선호 편향 검토의 선례.
- [Prometheus 2, EMNLP 2024](https://aclanthology.org/2024.emnlp-main.248/): 사용자 정의 기준에 따른 직접 평가와 쌍별 순위 평가의 선례.

논문용 방법 설명: “원천 문맥 기반 평가와 쌍별 언어모델 평가를 참고하여, 동일한 공통 근거에 대한 익명 분석 결과를 세 기준별로 개별 판정하였다. 후보 위치는 비교 단위별로 균형 있게 무작위 배치했으며, 사전에 층화 추출한 30% 표본에서 후보 순서를 교환하여 판정 일치율을 별도로 측정하였다. 각 후보의 실제 입력에 대한 근거 충실도는 별도 표본검사로 검토하였다.”

위 문장은 설계가 아니라 실제 평가가 완료된 후에 사용한다. 현재 BERTScore 결과와 아직 수행하지 않은 Judge·사람 검증 결과를 구분한다.
