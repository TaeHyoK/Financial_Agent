작성 기준: 2026-09-18. 현재 완료된 실험과 실제 실행·평가 코드를 기준으로 정리했다. 과거 실험의 뉴스 상위 20건, 월별 최대 2건, 재정렬 적용, 뉴스 분석에 월별 요약 제공 방식은 현재 실험에 적용하지 않는다.

## 2. 실험 목적과 범위

다음 세 요소가 기업 분석에 미치는 영향을 비교한다.

- DART 정보를 활용한 대상기업 관련 뉴스 선정.
- 하위 에이전트 분석 단계에서 다른 도메인의 보조자료 활용.
- 비교기업 분석을 통한 대상기업 판단 보완.

One-team은 역할별 분석을 하나의 통합 분석으로 바꾼 구조 비교 조건이다. Full과 동일한 원천 자료를 사용하지만, 하나의 문맥에서 모든 도메인의 상세 자료를 함께 볼 수 있다. 따라서 역할 분리뿐 아니라 문맥 공유 방식과 호출 수도 달라진다.

최종 비교 대상은 5개 기업, 조건은 5개, 각 조건의 생성 횟수는 3회다. 총 75개 최종 보고서를 평가했다. 처음 수집·1회 실행에는 삼성전자와 코웨이도 포함했지만, 추가 2회 생성과 현재 3회 평균 비교에서는 제외했다.

|---|---|---|---|
| 현대건설 | GS건설 | 2025-10-20 | 2024-10-20~2025-10-19 |
| 두산 | SK | 2025-11-11 | 2024-11-11~2025-11-10 |

기준일은 비교하는 실제 애널리스트 보고서의 작성일이다. 생성 파이프라인은 기준일 장 시작 전을 분석 시점으로 두므로 자료의 마지막 날짜는 전날이다. 실제 보고서의 당일 정보까지 완전히 동일하게 제공했다고 해석하지 않는다. 투자 전망 기간은 향후 12개월이다.

## 3. 공통 원자료와 전처리

### 재무 자료

기준일 이전에 공개된 DART 공시를 사용한다. 최근 3개 연도의 연간 재무제표와 최신 중간보고서, 전년 동기 자료를 구성하고 기간·공개일·연결/별도 기준을 보존한다. 동일 기업의 모든 조건은 같은 공시 원자료를 사용한다. 보조자료 제거 때문에 공통 가치평가 계산에 필요한 재무 수치까지 지우지는 않는다.

### 시장 자료

뉴스와 같은 12개월 구간의 주가·거래량·KOSPI 자료와 지표를 구성한다. 원자료는 보관하고, 시장 에이전트에는 월별 관측치와 최근 20거래일 자료 등을 포함한 공통 입력을 제공한다. 전체 기간 자료를 없애고 최근 20거래일만 분석하는 방식은 아니다. 지표 계산에 필요한 기준일 이전 준비 구간과 실제 분석 구간은 구분한다.

### 뉴스 수집과 공통 품질 처리

Google News 기반 수집 결과에서 URL 중복을 정리하고 전체 후보의 제목·스니펫을 확보한다. 전체 기사 본문을 LLM에 제공하지 않는다. Full과 Random은 동일하게 확보한 스니펫 자료와 공통 품질 기준을 사용하며, 빈 스니펫은 분석 후보에서 제외한다.

기사 간 의미 중복은 제목·스니펫의 임베딩으로 처리한다. 현재 설정은 ISO 달력 주간 안에서 최대 168시간, 코사인 유사도 0.88 이상을 연결하는 방식이다. 연결된 기사들은 사건 묶음으로 구성한다. 단순히 모든 기사 쌍이 0.88 이상인 묶음이라는 뜻은 아니다.

대표 기사는 묶음 내 평균 임베딩 유사도가 높은 기사를 사용한다. 날짜가 여러 개인 묶음은 날짜별 대표 제목을 최대 1개씩 보존하여 사건 진행 내역을 함께 전달한다. 이 대표 기사 선정 방식에는 공시 관련성 점수를 사용하지 않는다.

Full과 Random은 후보에 기업 필터를 적용하는 시점이 달라 사건 묶음 자체가 다를 수 있다. 같은 전처리 알고리즘을 적용한다는 것이 두 조건의 묶음 ID까지 같다는 뜻은 아니다.

## 4. Full과 Random 뉴스 입력 생성

### Full

```text
12개월 뉴스 수집·URL 정리·전체 스니펫 확보
→ DART 관계회사 정보와 대상기업 언급에 기반한 기업 필터
→ 주간 의미 중복 병합·대표 기사와 날짜별 사건 내역 구성
→ 공시 섹션별 임베딩 유사도 계산·가중합
→ 주간 최대 3개 사건 선정
→ 선정 기사 전체를 기준일에 맞춘 12개 월 구간으로 배열
→ 뉴스 에이전트 주 자료로 전달
```

공시를 섹션별 문맥으로 구성하고, 섹션 내부 공시 조각과 기사 간 유사도에서 섹션별 점수를 구한다. 기본 설정은 최대 400자 공시 조각과 `BAAI/bge-m3` 임베딩을 사용하며, 섹션별 최고 유사도의 음수값은 0으로 처리해 고정 가중치로 합산한다.

| 공시 섹션 | 가중치 |
|---|---:|
| 매출 | 0.30 |
| 실적 | 0.20 |
| 주요 제품·서비스 | 0.15 |
| 계약·연구개발 | 0.15 |
| 원재료·생산설비 | 0.10 |
| 사업 개요 | 0.10 |

이 가중치는 사전에 정한 설계값이며 최적값을 실험으로 입증한 것은 아니다. 교차 인코더 재정렬은 사용하지 않는다. 선정 기사에 추가로 전체 상위 20건이나 월별 2건 상한을 적용하지 않는다.

### Random news

```text
Full과 같은 수집 원본·스니펫 품질 처리
→ DART 기업 필터를 적용하지 않은 후보에서 주간 의미 중복 병합
→ 같은 알고리즘으로 대표 기사와 날짜별 사건 내역 구성
→ Full의 주간×월 구간별 선정 수량과 일치하도록 무작위 추출
→ 선정 기사 전체를 같은 12개 월 구간으로 배열
→ 뉴스 에이전트 주 자료로 전달
```

Random 후보는 `news_events_prefilter`다. 기업 필터를 통과한 Full 후보에서만 무작위로 추출하지 않는다. 공시 섹션별 관련성 점수도 추출에 사용하지 않는다. 주간이 월 구간 경계에 걸칠 수 있으므로 주간과 월 구간을 함께 맞춘다. 단순히 연간 총 기사 수만 같게 만드는 방식은 아니다.

최초 표본은 기본 시드 20251031과 기준일·기업명·1회차 식별값으로 만든 안정적 시드를 사용한다. 추가 2회에서는 이 표본을 다시 뽑지 않고 그대로 사용했다. 즉 3회 결과의 변동은 같은 Random 표본에서 생성 결과가 달라지는 변동이며, 여러 Random 표본에 대한 검증은 아니다.

이번 조건은 **DART 기업 필터와 공시 관련성 선정을 함께 제거한 비교**다. 임베딩 순위 알고리즘 하나만의 제거 효과로 해석하면 안 된다. Random의 요약·분석에는 Full과 같은 기업 설명과 해당 조건의 보조자료가 제공되므로 DART 정보를 모든 단계에서 배제한 조건도 아니다.

## 5. 월별 뉴스 요약과 하위 에이전트 입력

선정한 동일 기사들을 월별로 각각 요약한다. 기업·조건당 12개 월 구간을 독립 요청으로 처리하므로 요약은 12회 호출한다. 요약 모델은 `gpt-5.6-luna`이며 Full과 Random은 각자 선정한 기사로 별도의 요약을 생성한다. Random에 Full 요약을 복사하지 않는다.

요약은 사건별로 사용한 해당 월의 기사 ID를 기록한다. 월 구간, 실제 인용 ID와 입력 전체 ID를 구분한다. 요약에서 인용하지 않았다는 이유로 기사를 뉴스 주 자료에서 제거하지 않는다. 같은 월별 요약 근거를 인용한 사건이라도 분석 내용이 다르면 하나로 합치지 않는다.

| 하위 에이전트 | 주 자료 | 보조자료 |
|---|---|---|
| 재무 | 공시 기반 재무 자료 | 시장 지표표 + 월별 뉴스 요약 |
| 뉴스 | 선정 기사 전체: 날짜·제목·스니펫·기사 ID·사건 진행 내역 | 재무 추세표 + 시장 지표표 |
| 시장 | 시장 관측치·지표와 공통 시장 입력 | 재무 추세표 + 월별 뉴스 요약 |

뉴스 에이전트에는 뉴스 월별 요약을 넣지 않는다. 보조자료는 자기 도메인의 주 자료를 대체하지 않으며, 서로 다른 실적 시점·기업·연결/별도 수치를 하나로 합치지 않도록 지침을 적용한다.

## 6. 다섯 조건의 차이

| 조건 | 뉴스 주 자료 | 하위 에이전트 보조자료 | 비교기업 | 분석 구조 |
|---|---|---|---|---|
| Full | DART 기업 필터 + 섹션별 유사도 선정 | 제공 | 제공 | 재무·뉴스·시장 독립 분석 |
| Random news | 기업 필터 전 후보에서 수량을 맞춘 무작위 선정 | 제공; 뉴스 요약도 Random 자체 자료 | 제공 | Full과 동일 |
| No-subdata | Full과 동일 | 다른 도메인 보조자료 제거 | 제공 | Full과 동일 |
| No-peer | Full과 동일 | Full과 동일 | 제거 | 같은 회차 Full의 대상기업 하위 분석 공유 |
| One-team | Full과 동일 | Full의 영역별 입력에 포함된 자료 유지 | 제공 | 기업당 재무·뉴스·시장 통합 분석 1회 |

No-subdata는 대상기업과 비교기업 모두에서 보조자료를 제거한다. 뉴스 선정을 다시 하거나 주 자료를 줄이지 않는다. 월별 뉴스 요약은 사용하지 않으므로 새로 생성하지 않는다. 다만 공통 가치평가용 재무 계산은 보존하고 Strategy의 최종 종합은 유지한다. 따라서 모든 단계의 교차 도메인 판단을 제거하는 실험은 아니다.

No-peer는 같은 회차 Full의 대상기업 재무·뉴스·시장 결과를 그대로 사용한다. 비교기업 분석·쌍별 비교·비교 근거를 후속 입력에서 제거하고 Strategy·Writer를 새로 생성한다. 서로 다른 회차나 이전 실험의 Full 분석을 복사하지 않는다.

One-team은 각 도메인의 Full 전처리 입력과 분석 지침을 하나의 요청으로 구성한다. 이전 Full 하위 에이전트의 분석 문장을 입력으로 사용하는 방식은 아니다. 대상기업과 비교기업을 각각 통합 분석한 뒤 같은 후속 비교·Strategy·Writer로 연결한다. 출력은 세 개의 독립 도메인 보고서가 아니라 하나의 기업 분석과 근거 ID다.

모든 조건의 하위 분석·비교 분석·Strategy·Writer 모델은 `gpt-5.4`, 서비스 방식은 Standard다. 도메인 분석의 온도는 0.2, 추론은 none이며 Full의 도메인별 최대 출력은 12,000토큰, One-team의 기업별 최대 출력은 36,000토큰이다. 이는 최대 예산을 맞춘 것이지 실제 사용량을 같게 만든 것은 아니다. 조건별로 Full이 유리하도록 분석 지침이나 평가 기준을 달리하지 않는다.

## 7. 최종 보고서 생성과 반복 실행

```text
대상기업·비교기업의 하위 분석
→ 동일 기준의 지표 비교 자료 구성
→ LLM 비교 분석
→ Strategy: 분석·찬반 근거 검토와 최종 12개월 의견
→ 차트 목록 구성
→ Writer: Strategy 근거를 활용한 본문 편집·차트 선택·해석 작성
→ 선택 차트 생성
→ HTML 렌더링·기업 폴더 최상위에 게시
```

No-peer는 비교기업 및 LLM 비교 분석 단계를 생략한다. 차트 목록 구성·차트 생성·HTML 렌더링은 로컬 처리이며 별도 생성 모델 호출이 아니다.

이번 추가 2회 실행에서 재사용한 단계는 수집, 전처리, Full·Random 뉴스 선정, 월별 요약까지다. 하위 분석부터 최종 보고서까지 새로 생성했다. One-team도 대상기업·비교기업 통합 분석을 다시 생성했다. No-peer의 같은 회차 Full 공유 외에는 이전 분석 결과를 다음 회차에 재사용하지 않았다.

| 조건 | 추가 회차의 기업당 LLM 호출 수 | 구성 |
|---|---:|---|
| Full | 9 | 하위 분석 6 + 비교 1 + Strategy 1 + Writer 1 |
| Random news | 9 | Full과 동일 |
| No-subdata | 9 | Full과 동일 |
| No-peer | 2 | 같은 회차 Full 하위 분석 공유 + Strategy 1 + Writer 1 |
| One-team | 5 | 통합 분석 2 + 비교 1 + Strategy 1 + Writer 1 |

5개 기업 × 2회 추가 실행은 총 340회 호출, 50개 보고서다. 모두 완료했으며 실제 기록 토큰은 14,928,660개, 표준 단가 기준 추정 비용은 $55.982809다. 이는 추가 2회 실행 비용으로 최초 생성·수집·이전 요약 비용을 포함하지 않는다.

입력·코드 해시와 상태를 보존하며 완료 단계는 재실행하지 않는다. GPT-5.4 응답은 저장한 뒤 구조와 근거 연결을 검증한다. 의미·형식 오류가 났다는 이유로 조건별 프롬프트를 바꾸거나 자동 재생성하지 않는다.

예외 기록: 아모레퍼시픽 3회차 One-team은 Writer 응답 생성 후 차트 근거 카드 연결 검증에서 실패했다. 기존 유효한 직접 근거 카드는 유지하고 추가 통합 카드 연결 2건만 제거하여 오프라인 복구했다. 본문·투자의견·차트 설명은 바꾸지 않았으며 추가 LLM 호출은 없었다. 원본 응답과 변경 내역을 따로 보존했고 평가 본문은 그대로다.

## 8. 실제 애널리스트 보고서와 BERTScore 비교

기업마다 기준일의 실제 애널리스트 보고서 PDF 1개를 고정한다. 모든 조건과 회차는 그 기업의 동일한 보고서를 정답 참조 문서로 사용한다.

PDF에서는 사전에 검토한 페이지·좌표 영역의 서술 본문만 추출한다. 표, 예측 재무제표 표, 차트, 주가 정보, 연락처와 고지문은 제외한다. 서술형 실적 전망과 그 문장 안의 숫자, 서술형 실적발표 질의응답은 포함한다. 점수가 잘 나오는 영역으로 조건마다 바꾸지 않는다.

생성 HTML에서는 `section.report-section`의 문단과 목록을 추출한다. 표·그림·차트 영역·소제목·스크립트 등을 제외한다. PDF와 HTML의 레이아웃 차이 때문에 추출 구현은 다르지만 양쪽 모두 서술 본문이라는 같은 비교 범위를 사용한다.

| BERTScore 설정 | 값 |
|---|---|
| 구현 | 로컬 `bert_score.score` |
| 모델 | BAAI/bge-m3 |
| 층 | 24 |
| IDF | 사용하지 않음 |
| 기준선 재조정 | 사용하지 않음 |
| 배치 크기 | 1 |
| 실행 장치 | 서버 GPU, cuda:2 |
| 본문 잘림 | 허용하지 않음 |
| 보고 지표 | F1 중심; Precision·Recall도 보존 |

모델 토크나이저 한도 8,192토큰 안에서 전체 본문을 사용한다. 실제 BERTScore 인코딩 결과도 비교하여 자동 잘림을 확인한다. 한도 초과나 깨진 문자가 확인되면 일부만 잘라 점수를 내는 대신 오류로 처리한다.

기존 1회차의 25개 점수는 참조 문서·본문·생성 보고서 해시와 추출·평가 코드가 같은지 확인해 재사용했다. 추가 2회차의 50개 점수를 새로 계산해 총 75개 점수를 집계했다. 유료 LLM 평가 호출은 없다.

### 평균과 표준편차

기업 c, 조건 a, 회차 r의 F1 점수를 s(c,a,r)로 둔다.

- 기업·조건별 평균: `μ(c,a) = [s(c,a,1) + s(c,a,2) + s(c,a,3)] / 3`.
- 기업·조건별 표준편차: `SD(c,a) = sqrt(Σr[s(c,a,r) − μ(c,a)]² / 2)`. 표본 표준편차로 분모는 n−1이다.
- 조건별 전체 평균: 5개 기업의 평균 점수를 동일 가중치로 평균한다.
- 전체 평균 행의 표준편차: 먼저 회차별로 5개 기업 평균을 구한 후, 그 3개 회차 평균의 표본 표준편차를 계산한다. 기업 간 표준편차나 15개 개별 점수의 표준편차와 구분한다.

Random 표본과 월별 요약이 고정되어 있으므로 표준편차는 그 입력에서의 생성 반복 변동을 나타낸다. 3회 평균·표준편차만으로 통계적 유의성을 주장하지 않는다.

## 9. 산출한 평가와 아직 산출하지 않은 평가

이번 75개 보고서의 3회 평균 결과는 BERTScore다. 기존 1회차 평가에는 ROUGE-L도 있지만, 추가 2회까지 포함한 ROUGE-L 평균은 이번 작업에서 계산하지 않았다.

LLM 정성 평가와 뉴스 요약 인용 보존율은 논의된 별도 평가이며, 이번 75개 보고서의 완료된 점수표에는 포함하지 않았다. 과거 한 기업 실험의 평가나 보존율을 이번 실험 결과로 가져오지 않는다. 중요 사건 누락률은 사용자 합의에 따라 평가에서 제외한다.

요약 인용 보존율을 추가한다면 `(월 구간, 기사 ID)` 기준으로 요약에서 실제 인용한 고유 입력 수를 전체 고유 입력 수로 나눈다. 입력 전체 ID를 자동으로 인용 ID에 붙이지 않는다. 보존율은 인용률이며 높은 값만으로 기사 유용성이나 사실 정확성을 보증하지 않는다. 같은 요약을 3회 재사용했으므로 보존율을 독립 3회 생성 결과처럼 집계해서도 안 된다.

## 11. 다른 ChatGPT에 전달할 해석 지침

이 문서를 현재 구현 설명으로 사용하고 완료된 결과와 추가 평가 제안을 구분한다. Git 저장소만으로 서버 전용 실행기와 평가 결과까지 있다고 가정하지 않는다. Full이 모든 조건보다 우수하다는 결론을 전제하지 않고, 동일 기업·동일 기준일·동일 입력 정책에서 조건별 차이를 해석한다.

특히 Random은 기업 필터와 관련성 선정을 함께 제거한 조건, No-subdata는 하위 분석 보조자료 제거 조건, No-peer는 같은 회차 Full 분석을 공유한 비교 근거 제거 조건, One-team은 정보 접근 문맥과 분석 호출 수까지 달라지는 구조 비교 조건이라는 정의를 유지한다. BERTScore 유사도와 분석의 실제 정확성은 구분한다.
