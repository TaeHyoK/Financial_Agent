# 월별 뉴스 입력과 보고서 서술 보완

현재 운영 기준은 [뉴스 주 자료와 월별 요약 보조자료](news_article_only.md)이다. 뉴스 분석에는 선정 기사 전체를, 재무·시장 보조자료에는 월별 요약을 제공한다. 아래 월별 2건 설명과 실험 결과는 이전 방식의 기록이다.

작성일: 2026-09-10. 코드 반영 및 오프라인 검증 기록이다. 새 보고서를 생성하거나 기존 보고서를 덮어쓰지는 않았다.

## 뉴스 입력

현재 운영 기준(2026-09-14): 기준일 직전 1년 수집 → URL 정리·전체 스니펫 확보·기업 필터 → 주간 의미 중복 병합 → 기업보고서 섹션별 임베딩 유사도의 가중합으로 주별 최대 3건을 선정한다. 교차 인코더 재정렬은 제거했다. 아래 날짜별 검증 결과는 당시 코드의 기록이다.

2026-09-13에 주별 최종 선정 기본값을 5건에서 3건으로 변경했다. 대상기업과 비교기업에 같은 설정을 적용하며, Random은 새 Full 자료의 실제 주별·월 구간별 선정 건수에 맞춘다. Random에 별도로 고정되어 있던 5건 상한은 제거했다. 월별 요약 12개와 개별 기사 월별 최대 2건은 유지한다. 기존 저장 입력·요약·실험 결과와 과거 가중치 비교 실험 스크립트는 변경하지 않았다. 새 조건으로 비교하려면 Full 선정 자료와 Random 입력을 다시 준비하고 두 조건의 요약을 다시 생성해야 한다. 오프라인 테스트 FINAL 159개·ABLATION 86개가 통과했으며 유료 호출은 하지 않았다.

주별 선정 결과를 두 용도로 사용한다.

- 월별 요약 12개: 주별 선정 자료 전체로 생성하며 News의 주 자료와 Financial·YFinance의 보조자료로 제공한다. 월별 2건으로 요약 원자료까지 줄이지 않는다.
- 개별 기사: 주별 선정 자료 중 섹션별 임베딩 유사도의 가중 점수가 높은 기사를 월별 최대 2건씩 선택하고 날짜순으로 제공한다. 연간 최대 24건이며 부족한 월의 자리를 다른 월로 채우지 않는다. 제목·스니펫·사건 진행 내역을 유지한다.

월 구간은 기존 월별 요약과 같은 기준일 정렬 구간이다. 예를 들어 기준일이 2025-11-06이면 마지막 구간은 2025-10-06~2025-11-05다. 달력의 1일~말일 구간으로 바꾼 것은 아니다.

정책 식별자는 `monthly_raw_news_v1`, 언어모델 입력 키는 `월별 기업 뉴스(최대 2건)`이다. 저장 파일 `recent_raw_input.json` 및 내부 경로 접근자 `news_company_top20`은 호환을 위해 유지하되 실제 내용은 월별 최대 24건이다. 월별 입력을 예전 20건 한도로 잘라 전달하려는 호출은 오류로 알린다.

기본 설정은 `configs/news_default.yaml`의 `monthly_top_k: 2`다. 명시적인 `--news-event-top-k`는 과거 전체 순위 방식으로 되돌리는 호환 옵션이므로 새 연간 실험에서는 사용하지 않는다.

## 실험 조건

Full과 one_team은 같은 월별 입력을 받는다. Random은 같은 중복 병합 후보에서 주간×월간 구간별 개수를 Full과 일치시켜 요약용 기사를 무작위로 선택한다. 이후 그 집합 안에서 월별 최종 기사 개수도 Full과 맞춘다. 이렇게 해야 월 경계를 가로지르는 주에서도 요약과 개별 기사의 월별 자료량이 달라지지 않는다.

Random의 월별 요약은 무작위 선정 자료로 다시 생성해 News·Financial·YFinance에 함께 반영한다. 대상기업과 비교기업에 같은 처리를 적용한다. Full·Random 모두 언어모델에 선정 점수와 순위를 제공하지 않는다. 기사의 길이와 내용까지 동일한 것은 아니므로 실제 토큰 사용량은 별도로 비교해야 한다.

계약은 `random_news_v4_week_month_matched_monthly_raw`다. 연간 실행 전 공통 원본의 월별 정책, 전달 자료 정책, 선정 기사 식별자의 일치를 확인한다. 예전 전체 상위 20건 원본을 그대로 쓰면 중단한다. 새 원본과 새 실험 디렉터리가 필요하다.

## 보고서에서 뉴스가 약하게 나타난 이유와 수정

저장된 SK바이오팜 분석 보존 실험 2회차의 Strategy 문맥에는 뉴스 근거 카드 6개가 있었고, Writer 전달 자료에도 그중 5개가 남아 있었다. 이 사례에서는 단순 전달 누락보다 사건을 짧게 언급하고 실적 기여가 확인되지 않았다는 설명으로 끝내는 경향이 문제였다. 이 결과는 실험용 분석 보존 경로의 사례이며 모든 운영 보고서에 동일하다고 단정하지 않는다.

News·Strategy·Writer 지침을 다음과 같이 보완했다.

- 공시는 기존 사업·실적의 기준, 뉴스는 관찰기간 중 변화한 사실로 구분해 활용한다.
- 중요한 사건은 무엇이 바뀌었는지, 기존 사업에 어떤 의미인지, 향후 12개월 전망이나 전제를 어떻게 보강·수정하는지 연결한다.
- 같은 제품에 관한 기사라도 실적·계약·허가·출시·안전성 사건을 구분하고 날짜와 근거를 보존한다.
- 실적 반영 규모를 모르면 수치를 만들지 않되, 입력에서 확인되는 사업적 의미까지 생략하지 않는다.
- 최종 의견의 결정적 근거가 아니어도 전망이나 사업 진행 상황을 설명하는 데 활용할 수 있다. 뉴스 문장 수나 비중을 강제하지 않는다.

기존 요청·결과 캐시를 구분하기 위해 Strategy 캐시 버전은 15, Writer는 19로 변경했다. 실험용 분석 단계 프롬프트에도 같은 원칙을 반영했다. 관련 문맥과 작업별 지시를 명확하게 제공하는 방향은 [OpenAI 프롬프트 작성 문서](https://developers.openai.com/api/docs/guides/prompt-engineering)를 참고했다.

## 오프라인 확인

기존 섹션 가중치 실험에 저장된 주별 후보와 점수로 다시 선정했다. 원본은 수정하지 않았다.

| 기업 | 기존 개별 기사 | 월별 선정 | 기존과 공통 |
| --- | ---: | ---: | ---: |
| SK바이오팜 | 20 | 24 | 16 |
| 유한양행 | 20 | 24 | 12 |
| 코웨이 | 20 | 24 | 13 |
| 쿠쿠홀딩스 | 20 | 21 | 17 |

SK바이오팜은 기존 개별 기사 입력이 비어 있던 3개 월 구간에 기사가 추가됐다. 모든 기업에서 Full과 Random의 월별 최종 개수 및 요약용 주간×월간 개수가 일치한다. 이는 기간 분산 확인이지 뉴스 품질이나 Full의 우월성 검증은 아니다.

유효 결과: `/home/agent2/ABLATION/experiments/monthly_news_20260910_offline_v2/audit.md`.

첫 오프라인 산출 폴더 `monthly_news_20260910_offline`는 과거 실험의 점수 필드 차이를 처리하지 못한 잘못된 재선정이다. `INVALID.md`로 표시했고 결과로 사용하지 않는다. 수정한 도구는 과거 섹션 가중치 자료의 `final_score`와 운영 자료의 `rel_rerank`를 구분하고 점수가 없으면 중단한다. 두 실행 모두 API를 호출하지 않았다.

네트워크를 차단한 테스트: FINAL 116개, ABLATION 85개 통과. 월별 24건의 실제 News 요청 전달, 20건 재절단 거부, 월 경계, 부족한 월, 무작위 재현성·개수 일치, 오래된 원본·불일치 전달 자료 거부를 포함한다.

## 남은 확인

월별 배분만으로 기사 품질을 해결하지는 않는다. 저장 자료의 재선정 결과에는 같은 실적 발표나 허가를 다룬 유사 기사 쌍이 남는다. SK바이오사이언스를 다룬 제목도 SK바이오팜 입력에 남아 있어 기업 식별·관련성의 별도 점검이 필요하다. 이번에는 특정 기업명에 맞춘 예외 규칙이나 추가 중복 병합을 넣지 않았다.

월별 요약의 기존 분량 지침·검사는 변경하지 않았다. 새 지침으로 최종 보고서의 뉴스 해석이 실제 좋아지는지는 아직 확인하지 않았다. 다음 검증은 mini 모델을 사용한 제한된 재실행으로 하되, 실행 구간과 입력·출력 예상량을 먼저 확인한다. 이번 작업의 유료 API 호출은 0회다.
