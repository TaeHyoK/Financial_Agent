# 뉴스 주 자료와 월별 요약 보조자료

2026-09-14 운영 반영. 이후 일괄 요약 4회와 월별 개별 요약 48회를 비교했다. 최신 사용 대상은 월별 개별 호출 결과이며, 새 보고서는 생성하지 않았다.

## 처리와 전달

전체 후보 스니펫 확보 → 기업 필터 → 주간 중복 병합 → 공시 섹션별 가중 임베딩 유사도 상위 3건/주 → 월별 기사 배열 → 하위 분석.

- 교차 인코더를 사용하지 않는다. 뉴스 주 자료에 월별 2건·연간 24건의 추가 제한이나 요약에 인용된 기사만 통과시키는 처리를 적용하지 않는다.
- 뉴스 에이전트는 `News/{기준일}/context_exports/month/selected_articles.json`의 선정 기사 전체를 받는다. 기사 ID·날짜·제목·스니펫·진행 내역을 보존하며 월별 요약을 뉴스 분석 입력에 추가하지 않는다.
- 재무·시장 에이전트는 같은 선정 기사에서 생성한 `llm_period_summaries.json`의 월별 요약을 동일하게 받는다. 이 두 에이전트에는 개별 기사 전체를 중복 입력하지 않는다. 월별 요약은 원문이나 공시 확정치가 아닌 LLM이 정리한 보조자료로 명시한다.
- 월별 요약의 본문은 `periods[].issues[]`에 사건별 `summary`와 실제 사용한 `source_event_ids`로 작성한다. 같은 기사를 인용해도 독립 사건은 별도 항목으로 유지하며 재무·시장에 사건별 설명과 인용 ID를 그대로 전달한다. 월 전체 서술을 별도로 중복 생성하지 않는다.
- 월 구간은 배열 기준이며 사건 발생일이나 실적 대상 기간이 아니다. 기사별 근거를 유지하고, 같은 달이라는 이유로 별개 사건을 합치지 않도록 지침을 수정했다. Strategy·Writer도 같은 구분을 따른다.
- 대상기업과 비교기업에 동일하게 적용한다. 공시 섹션 분할·가중치·기업 필터·중복 기준은 이번 변경에서 유지했다.

## 실험 조건

Full은 기업 필터 후 공시 임베딩 유사도로 선정한다. Random은 기업 필터 전 중복 처리 집합에서 무작위 추출한다. 기존 실험 정의처럼 기업 필터와 관련성 선정을 함께 제거한 조건이다. 주간×월간 구간별 기사 수는 Full과 맞추며, 두 조건의 스니펫 제공 방식과 후속 프롬프트는 같다. 길이가 달라 토큰 수까지 같지는 않다.

Full·Random은 각각 선정한 기사로 월별 요약을 만든다. 요약 프롬프트·모델·호출 방식은 같고, Random에 Full의 요약을 복사해 사용하지 않는다.

`no_subdata`는 뉴스 주 자료를 유지하고 다른 도메인의 보조자료만 제거한다. 신규 실행에서 사용하지 않을 요약은 호출하지 않는다. `one_team`은 Full과 동일한 영역별 입력(뉴스는 개별 기사, 재무·시장의 뉴스 보조자료는 요약)을 받는다. 새 전체 비교는 입력·프롬프트가 바뀐 분석 결과를 다시 생성해야 한다.

## 실행 및 캐시

최신 합의는 **월별 개별 호출**이다. `/home/agent2/ABLATION/experiments/news_linked_summary_monthly_gpt54_20260914/review.md`에 48회 실행 결과를 기록했다. 운영 CLI 기본값은 아직 일괄 방식이므로 신규 실행은 `--news-split-by-period`(하위 뉴스 CLI는 `--split-by-period`)를 명시해야 한다. 아래 기본 호출 수 11회는 일괄 설정의 설명이며 월별 신규 실행의 호출 수가 아니다. 월별 신규 실행은 비교기업 포함 조건당 33회(요약 24 + 하위 분석 6 + 후속 3), 요약까지 재사용하면 조건당 9회다.

- `export`는 선정 기사 파일과 요약 요청을 준비한다. 뉴스 분석은 기사 파일을, 재무·시장 분석은 `news_llm`에서 생성한 월별 요약을 사용한다. 기존 요약 생성기를 재사용하며 새 요약 전용 에이전트는 추가하지 않았다.
- 기본은 회사당 12개월 요약을 한 번에 요청한다. 비교기업 포함 신규 전체 실행은 요약 2회 + 하위 분석 6회 + 비교 분석·Strategy·Writer 3회 = 11회다. 요약까지 저장한 입력을 재사용하면 9회이며, 월별 개별 호출 옵션이나 재시도는 별도다. 모델 설정은 기존 값을 유지했다.
- 기사 정책은 `monthly_selected_articles_v1`, 보조자료 정책은 `monthly_summary_v1`이다. 저장 자료 재사용 시 기사 파일과 주별 선정 원본, 요약 요청 해시와 출력 모델을 확인한다. 기사 내용이나 요약 지침이 다른 과거 결과는 재사용하지 않는다.
- 변경 전 백업: `/tmp/news_raw_production_stGt1B/before.tar.gz`. 기존 실험 결과는 변경하지 않았다.

## 요약 복원 보완

2026-09-14 추가 수정. 입력에 없는 `mention_count` 합산 지침과 요약 출력의 중요도·이유 필드를 제거했다. 사건별 설명에 필요한 내용만 작성하며 400자·3개 안팎 같은 분량 목표도 제거했다. 새로운 에이전트나 추가 호출은 없다.

- 모델은 각 사건의 근거로 사용한 해당 월의 입력 `event_id`를 문자열 그대로 출력한다. 원문 기사의 뉴스 에이전트 입력은 이 선택과 무관하게 전부 유지한다.
- 저장 결과의 월별 `input_event_ids`는 입력 전체, `source_event_ids`는 사건별 실제 인용 ID의 중복 없는 합집합이다. Python이 입력 전체를 실제 인용으로 붙이지 않는다.
- 검사는 JSON 구조·월 구간·ID 존재 여부에 한정한다. 중요도 판단, 사건 수 제한, 인용 수 제한, 잘못된 근거의 임의 교체는 하지 않는다. 근거로 사용할 사건이 없으면 빈 `issues`를 허용하며 고정 해설을 삽입하지 않는다.
- 보존율은 같은 기업·조건 안에서 `(월 구간, event_id)` 기준 실제 인용 고유 개수 / 입력 고유 개수로 계산할 수 있다. 분모가 0이면 해당 없음으로 처리한다. 이는 모델이 기록한 인용률이지 내용의 정확성이나 기사 중요도를 보증하는 지표는 아니다. 이번에는 평가 실행기를 새로 추가하지 않았다.
- 요약 요청 해시가 바뀌므로 이전 요약은 새 실행의 캐시로 사용할 수 없다. 과거 결과 열람을 위한 기존 요약 읽기는 유지한다. 기본 모델과 회사당 1회 호출 방식, 월별 분할 호출 옵션은 변경하지 않았다.

### 비용 가정

[OpenAI 공식 표준 단가](https://developers.openai.com/api/docs/pricing)를 적용했다. 캐시 할인·재시도는 제외했다. 하위 에이전트 출력이 각각 4,000~12,000토큰인 경우:

| 모델 | Full 하위 분석 6회 | Random 하위 분석 6회 | 두 조건 합계 |
|---|---:|---:|---:|
