# 뉴스 입력·근거 전달 수정 기록

2026-09-13 후속 변경: 뉴스 상태 판단 지시와 월별 요약의 분량 상한 등은 [프롬프트·출력 계약 정리](prompt_alignment_20260913.md)에 기록했다. 기사 선정 방식과 전체 스니펫 재처리의 미완료 상태는 그대로다.

## 1단계: 근거 전달 수정 — 2026-09-10 완료

- News → Strategy에서 근거 ID 공유 여부로 분석 항목을 병합하던 함수를 제거했다. 분석 항목별 주장과 근거를 각각 카드로 보존한다. 같은 기사에 대한 서로 다른 해석도 합치지 않는다.
- 뉴스 파서가 대표 근거 필드를 삭제하지 않도록 했다. 기사·월별 요약 모두 대표 근거가 될 수 있다.
- 대표 근거 ID는 추적용 provenance에, 자료 유형·제목·자료 날짜는 Strategy 카드에 전달한다. 원시 ID를 Strategy 본문에 노출하지 않는 기존 구조는 유지한다.
- 월별 요약의 출처를 같은 달 최종 선정 기사로 덮어쓰는 처리를 제거했다. 실제 요약 입력 기사 목록은 source_event_ids에 보존하고, LLM에는 요약 ID와 출처 기사 수를 제공한다.
- 월별 요약이 대표 근거인 경우 보조적으로 인용한 기사 날짜를 사건 발생일로 사용하지 않는다. 주장에 직접 대응하는 자료를 대표 근거로 지정하도록 뉴스 프롬프트를 수정했다.
- 대표 근거가 카탈로그에 없으면 다른 기사로 대체하지 않고 입력 오류를 알린다. 의미적 적합성을 판정하는 규칙이나 별도 검증 에이전트는 추가하지 않았다.
- Strategy 캐시 버전은 16으로 변경했다. 기존 뉴스 산출물의 잘못된 인용을 자동으로 교정한 것은 아니다.

## 2단계: 스니펫 공통 처리 — 구현·소규모 검증 완료

- Full 수집 파이프라인의 스니펫 처리 범위를 최종 기사에서 주별 요약 입력 기사까지 확대했다. 선정이 끝난 뒤 처리하므로 기존 순위와 월별 최대 2건 정책은 바꾸지 않는다.
- 기존 수집 함수를 재사용하는 `collectors/report_snippets.py`를 추가했다. Full·random 자료를 함께 전달하면 필요한 대표 기사 합집합을 한 번 처리한다.
- 기존 실행 순서에서는 먼저 처리한 Full의 스니펫을 random이 재사용하고, 새로 필요한 기사만 같은 함수로 처리한다. 수집 실패도 기록해 동일 기사에 조건별로 추가 기회를 주지 않는다. 원본 Full 자료는 수정하지 않는다.
- 짧은 발췌 기준은 기존 280자 기준을 유지한다. 실패한 기사를 다른 기사로 바꾸거나 LLM으로 내용을 생성하지 않는다.
- 기사 처리 여부와 발췌 출처를 대표 기사 메타데이터에 저장한다. 오래된 제목 전용 자료나 바뀐 스니펫과 과거 요약 입력이 섞이면 실험 준비 단계에서 알린다. 이는 자료 일치 검사이며 투자 판단이나 뉴스 중요도 판정 규칙이 아니다.
- 과거 섹션 가중치 실험 코드의 스니펫 일괄 삭제를 제거했다. 순위 계산에는 기존처럼 제목만 사용한다. 평가 코드도 스니펫 0건을 강제하지 않고 실제 입력과 저장된 자료의 일치를 확인한다.
- HTML 원시 바이트를 파서에 전달해 문서 인코딩을 읽도록 수정했다. 이미지·동영상의 구조화된 설명과 figure/figcaption 영역은 기사 발췌에서 제외한다. 매체별 예외 목록이나 새로운 품질 판정 모델은 추가하지 않았다.
- 연간 random 전처리 프로토콜은 `random_news_v5_shared_snippets`로 변경했다.
