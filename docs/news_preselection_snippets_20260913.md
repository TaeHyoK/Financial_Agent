# 전체 후보 스니펫 선확보

## 변경한 순서

1. 요청 기간의 뉴스 후보를 수집하고 동일 URL을 정리한다.
2. 선택 여부와 관계없이 전체 후보의 스니펫 추출을 시도한다.
3. 제목·스니펫에 공통 기업 필터를 적용한다.
4. 통과한 기사의 제목·스니펫을 임베딩하고 같은 달력 주간의 의미 중복을 결합한다.
5. 동일한 전체 사건 후보에서 Full은 기업보고서 관련성으로, Random은 무작위로 선택한다.
6. 선택 자료로 요약과 하위 에이전트 분석을 진행한다.

스니펫은 언론사 페이지의 짧은 발췌문이며 추출에 LLM을 사용하지 않는다. 전체 본문을 LLM에 전달하지 않는다. 기존의 기사 선택 이후 스니펫 수집·대표 기사 교체 코드는 제거했다. 임베딩과 교차 인코더 모두 같은 제목·스니펫을 사용한다.

## 공통 기업 필터

- 스니펫이 없으면 분석 후보에서 제외한다.
- DART에서 대상기업, 연결대상 종속회사, 그 밖의 관계회사를 구분한다. 두 표에 함께 있는 회사는 연결대상 종속회사로 본다.
- 대상기업이 제목 또는 스니펫에 독립된 회사명으로 등장하면 유지한다. 다른 관계회사가 함께 등장해도 제외하지 않는다.
- 연결대상 종속회사만 등장한 기사도 후보로 유지한다. 연결 실적·사업에 대한 관련성은 후속 재정렬과 분석에서 판단한다.
- 인식한 회사가 그 밖의 관계회사뿐인 기사는 `other_related_only`로 제외한다.
- 인식한 회사명이 없는 기사는 `undetermined`로 기록하고 후보에 유지한다. 브랜드명·약칭만 있는 기사를 이름 미확인만으로 제외하지 않는다.
- `그룹`이라는 단어만으로 제외하지 않는다.
- 긴 법인명부터 인식한다. 예를 들어 `아모레퍼시픽홀딩스` 내부 문자열을 대상기업의 별도 언급으로 보지 않는다.
- 관계회사는 해당 실행의 DART 원문에서 계열회사 상세표와 연결대상 종속회사 상세표를 읽는다. 외국 계열회사 표도 회사명 열이 확인되면 포함하며, 최신 기업 관계를 별도로 소급 적용하지 않는다.
- 해당 상세 구역만 따로 파싱하고, 기존 재무 에이전트의 표 파서로 병합 셀을 펼친다. 열 개수·설립일 위치·법인등록번호 유무로 회사명 행을 추정하지 않고 머리글로 열을 찾는다.
- 입력 기업명·공시 법인명·같은 법인등록번호의 회사명을 대상기업 별칭으로 연결한다. LG 전용 문자열 변환은 제거했다.
- 확인된 대상기업 별칭에서 영문/한글 접두어 대응을 얻을 수 있으면 공시에 기재된 회사명에 한정해 표기 변형을 생성한다. 예를 들어 `AB전자/에이비전자`에서 얻은 대응을 기재된 `에이비화학`에 적용한다. 이는 명칭에 대한 추론이며 `derived_prefix_aliases`로 별도 기록한다. 공시에 이미 있는 다른 이름을 덮어쓰거나 새 지배관계를 만들지 않는다.
- 다른 회사명의 접두어이기도 한 관계회사명은 단독 문자열만으로 제외하지 않는다. 이 처리에 특정 기업명이나 글자 수 임계값은 사용하지 않는다.

이것은 기사 주제를 판정하는 의미 분류기가 아니다. 경쟁사 실적의 비교 대상으로 대상기업이 언급된 기사도 남을 수 있고, 해외법인의 한국어 통칭을 모두 인식하지 못한다. 이름이 불명확한 후보의 관련성은 후속 재정렬에 맡긴다. 기업명을 잘못 적은 기사 수치를 교정하지 않으므로, 분석 단계의 주체·기간·연결/별도 구분은 여전히 필요하다. 필터 판정 정보는 저장용 감사 자료이며 이를 위해 새 LLM 호출이나 중요도 규칙은 추가하지 않았다.

## 중복 처리와 공정한 비교

수집기의 제목 일치만을 이용한 선제 제거는 없앴다. 제목이 같아도 URL이 다르면 스니펫을 먼저 확인한다. 동일 URL의 중복 요청은 피한다. 의미 중복은 기존처럼 달력 주간 안에서 처리하며 이번 변경에서 주간 경계나 유사도 0.88을 바꾸지는 않았다.

Full은 기존의 섹션별 가중 유사도, 주간 후보 15건·확정 최대 3건, 월별 개별 기사 최대 2건을 유지한다. Random은 Full과 주·월 구간별 수량을 맞추되 관련성 점수를 사용하지 않는다. 후보가 부족한 기간은 필터를 완화하거나 다른 월 기사로 채우지 않는다.

Random 선택 후에는 스니펫을 가져오거나 별도 필터링을 하지 않는다. 공통 사건 후보의 발췌문을 그대로 재사용한다. 새 버전 입력에 예전 스니펫 보완 도구를 실행해도 네트워크 수집 없이 동결된 공통 후보를 확인한다.

위 내용은 현재 구현된 Random이다. 제안된 ‘기업 필터·DART 관련성 평가를 적용하지 않는 Random’은 아직 구현하지 않았다. 이번 수정은 기업 필터에 한정하며, 재정렬 입력 방향·가중치·중복 처리도 바꾸지 않았다.

입력 버전은 `all_snippets_then_entity_filter_v3`이다. v1·v2 기업 필터로 생성한 공통 후보도 새 실행에서 그대로 재사용하지 않는다. 옛 결과의 메타데이터만 바꾸지 말고 뉴스 전처리·선정·요약부터 새 디렉토리에 생성해야 한다. 기존 파일은 삭제하지 않았다. 기존 스냅샷을 스니펫 보완 도구에 넘겨도 선택 후 재수집으로 우회하지 않고 버전 불일치를 알린다.

표에 회사명이 있으면 `parsed`, 읽을 수 있는 표에 명시적으로 비어 있음을 표시하면 `empty`로 기록한다. 필요한 상세 구역·회사명 머리글을 찾지 못하거나 자료 행의 회사명을 읽지 못하면 원인과 함께 중단한다. 파싱 실패를 ‘관계회사 없음’으로 처리하지 않는다.

## 저장 자료

기업별 News 실행 폴더의 `artifacts/news/raw/{기업명}_{수집기준일}/`에 저장한다.

| 파일 | 내용 |
|---|---|
| `raw_news_attempts.parquet` | 스니펫 추출을 시도한 전체 후보. 확보 스니펫, 미확보 사유, 기업 필터 판정 보존 |
| `raw_news_candidates.parquet` | 공통 필터를 통과해 임베딩·중복 결합에 사용하는 기사 |
| `candidate_preparation.json` | 전체·통과 수, 제외 및 추출 실패 사유별 수, 공시 출처, 기준일에 맞춘 월별 후보 수 |

HTTP 상태 오류, 시간 초과, 원문 URL 미해결, 유효 발췌문 미확보를 구분해서 기록한다. 예전 캐시에 상세 실패 사유가 없으면 `not_recorded`로 남기며 원인을 추정하지 않는다. 후보가 모두 제외되면 기록을 저장하고 중단한다. 예전 보고서나 제목만 있는 기사로 대체하지 않는다. 기록 경로는 workflow manifest에도 남긴다.
