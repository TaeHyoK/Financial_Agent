# 뉴스 섹션별 가중치 적용

최종 수정: 2026-09-14. 적용 위치: FINAL 기본 뉴스 수집·선정 경로. 교차 인코더 재정렬을 제거하고 섹션별 임베딩 유사도로 직접 선정한다. 기존 실험 결과와 분석 프롬프트는 변경하지 않았다.

## 가중치와 처리

| 기업보고서 섹션 | 가중치 |
|---|---:|
| 매출 및 수주상황 | 0.30 |
| 손익계산서 | 0.20 |
| 주요 제품 및 서비스 | 0.15 |
| 주요계약 및 연구개발활동 | 0.15 |
| 원재료 및 생산설비 | 0.10 |
| 사업의 개요 | 0.10 |

설정: `configs/news_default.yaml → scoring.section_weighting`.

1. 기준일에 사용 가능한 기업보고서 XML에서 여섯 섹션을 읽는다. 손익계산서는 연결을 우선하고, 연결 손익계산서가 없는 경우 별도 손익계산서를 사용한다. 일반 손익계산서와 포괄손익계산서가 분리되어 있으면 일반 손익계산서를 우선한다.
2. 표의 열 제목과 TE·TU 등 수치 셀을 보존한다. 본문은 최대 400자 단위로 나누고 회사명·섹션명·공시일을 붙인다. 기존 키워드 점수나 섹션별 문단 개수 제한으로 내용을 다시 제거하지 않는다.
3. 각 기사와 각 섹션의 문단 사이 코사인 유사도를 계산한다. [0,1] 범위로 제한한 뒤 섹션별 최댓값의 가중합을 구한다.
4. 사건 대표 기사의 가중 점수로 ISO 달력 주별 최대 3건을 정해 세 하위 에이전트에 기사 자료로 제공한다. 동점이면 기사 날짜 내림차순, URL·사건 ID 오름차순으로 정한다. 교차 인코더 호출과 중간 15건 후보 단계는 없다.
5. 주별 선정 기사 전체를 월 구간별로 제공한다. 중간 요약과 추가 월별·연간 건수 제한은 없다. 현재 기사 전용 정책에서 전체 상위 건수 옵션은 입력을 자르지 않도록 거부한다. [기사 전달 구조](news_article_only.md)를 참고한다.

중복 병합과 대표 기사 선택에는 새 가중치를 적용하지 않았다. 재정렬 제거 후 별도 변경으로 중간 요약을 없애고 선정 기사 전체를 제공하도록 했다. 실험의 제목만 사용한 통제 조건과 실서비스의 스니펫 제공 조건은 구분해야 한다.

섹션별 임베딩 점수는 `scores.dense_section_scores`에 저장한다. `scores.rel_dense`와 `scores.final_score`는 같은 가중 점수다. `news_selection.stage`는 `section_weighted_dense_v2`, `reranking_enabled`는 `false`이며 `weekly_top_k`와 가중치를 함께 저장한다. 새 결과에는 재정렬 점수 필드가 없다. 주별 건수는 `configs/news_default.yaml → news.weekly_top_k`에서 설정한다.

## 실험과 재사용

- 대상기업과 비교기업 모두 같은 코드와 가중치를 사용한다.
- Random 실험 코드는 이번 운영 반영에서 변경하지 않는다. 새 비교는 해당 실험의 기업 필터 적용 여부를 명시하고 Full과 주간·월간 입력 건수를 맞춰야 한다. 가중 점수로 Random을 고르지 않는다.
- 기존 동결 자료와 보고서는 자동으로 재선정하지 않는다. 새 실험에서는 가중 선정과 월별 요약을 포함한 공통 자료를 새로 만들고 조건별로 공유해야 한다. Full만 새 자료로 바꾸어 기존 Random 결과와 비교하면 통제된 비교가 아니다.
- 원 자료의 스니펫 제공 차이는 가중치 적용만으로 해결되지 않는다. 제목만 쓰는 실험은 Full·Random에 공통으로 적용해야 한다.
- 가중치는 설계값이다. 기존 단일 기업·단일 반복 실험에서 최적성이나 성능 우위가 입증된 것은 아니다.

## 오류와 검증

섹션 누락·모호한 손익계산서, 이전 방식으로 만든 기업보고서 DB, 임베딩 모델 로딩 실패는 오류로 알린다. 누락 섹션의 가중치를 재분배하거나 해시·단어 중복 점수로 대체하지 않는다. 기존 섹션 분할과 임베딩 DB 형식은 유지하므로 이번 재정렬 제거만을 이유로 공시를 다시 임베딩할 필요는 없다.

2026-09-14 오프라인 검증 결과:

- FINAL 테스트 213개, ABLATION 호환성 테스트 92개 통과. 실험 코드는 변경하지 않았다.
- 아모레퍼시픽 후보 817건에서 159건, LG생활건강 후보 749건에서 157건을 재선정했으며 두 기업 모두 `amore_fourway_no_rerank_20260914` 실험의 선정 기사 ID와 완전히 일치했다.
- 주간 순위·동점 처리·월별 배분·통합 실행의 대상/비교기업 설정과 점수 기록을 확인했다. 유료 호출과 새 보고서 생성은 하지 않았다.

새 실행은 기본 설정을 읽는다. 과거 저장 자료를 명시적으로 재사용하면 그 안의 선정 결과와 요약은 변경되지 않는다. 예전 사용자 설정의 `weekly_rerank_top_k`는 주별 건수의 호환 이름으로만 읽으며 재정렬을 활성화하지 않는다. 삭제한 재정렬 구현은 작업 전 백업 `/tmp/news_dense_production_zer3Jb/before.tar.gz`에서 복구할 수 있다.
