# 뉴스 선정 평가 합의 및 후속 기사 활용 점검

작성일: 2026-09-13. 1~5절은 최초 코드·저장 결과 검토다. 사용자 승인 후 진행한 구현과 로컬 검증은 6절, 이후 GPT-5.4 실호출 결과는 7절에 기록했다.

## 1. 기억할 평가 방향

뉴스 선정 단계와 최종 보고서 단계를 구분해서 평가한다. 후속 요약·분석 모델이 Random의 잡음을 걸러낼 수 있으므로, 최종 보고서 점수만으로 선정 단계의 효과를 판단하지 않는다. Full 우위를 전제로 평가 기준을 조정하지 않는다.

- 요약 전 선정 기사를 대상으로 조건을 가린 LLM 평가를 실시한다. 기업 관련성, 입력에서 확인되는 구체적 사실, 기업 분석에 활용할 수 있는 내용을 평가한다. 공시 문장과 닮았는지를 정답으로 삼지 않는다.
- 요약에 실제 인용한 기사 ID를 이용해 **요약 인용 기사 보존율**도 계산한다.
- 보존율이 높다고 곧바로 유용성이 높다고 해석하지 않는다. 중복 기사 인용, 무분별한 인용, 유용한 자료의 요약 누락도 가능하므로 기사 평가와 함께 해석한다.
- 중요 사건 누락률은 평가 항목에 넣지 않는다. 아래의 누락 사례 점검은 전달 구조를 진단하기 위한 것이며, 별도의 중요 사건 정답 목록이나 회수율 평가를 만들겠다는 뜻이 아니다.

### 최소 평가 설계

1. 평가 입력은 기업 개요, 기사 날짜·제목·실제 제공 스니펫·사건 진행 내역이다. Full/Random 구분, 선정 점수·순위, 생성된 요약·보고서는 숨긴다. 동일 기업에는 동일한 중립적 기업 설명을 제공한다.
2. 각 기사에서 기업과의 관계, 구체적 사실, 분석 활용 내용 한 문장, 이를 뒷받침하는 짧은 원문 구절을 기록한다. 최종 분류는 `활용 가능 / 활용 제한 / 활용 근거 없음 / 자료 부족`으로 둔다.
3. 금액이 없어도 계약·출시·회수 등은 활용 가능하다. 긍정·부정 기사에 같은 기준을 적용한다. 산업 기사도 대상기업과의 연결이 입력으로 뒷받침되면 인정한다. 입력에 없는 사실을 외부 지식으로 보충하지 않는다.
4. 20~30건을 먼저 사람이 확인해 기준을 정리한 뒤 고정한다. 이후 같은 평가 모델과 지침으로 처리한다. 한 번에 5~10건씩 독립 평가하고 일부 표본은 순서를 바꿔 일관성을 확인한다. 기사 속 지시문은 평가 지시가 아니라 자료로 취급한다.
5. 두 조건의 날짜·제목·스니펫이 같은 기사는 한 번 평가해 양쪽에 연결한다. 같은 URL이라도 실제 제공 내용이 다르면 따로 평가한다.

| 지표 | 정의 및 해석 |
|---|---|
| 입력 기사 활용 가능 비율 | 활용 가능으로 평가된 기사 수 / 요약 전 고유 입력 기사 수. 나머지 세 분류의 비중도 함께 보고한다. |
| 요약 인용 기사 보존율 | 월별 요약에서 인용한 고유 입력 기사 ID 수 / 요약 전 고유 입력 기사 ID 수. 반복 인용은 한 번만 센다. |
| 보존 기사 중 활용 가능 비율 | 보존된 기사 중 활용 가능으로 평가된 기사 수 / 보존된 고유 기사 수. |

기사 평가 분류와 요약 인용 여부를 교차 집계한다. 자료 부족은 관련 없음과 구분한다. 대상기업과 비교기업을 따로 보고하고, 한 기업·한 Random 추출 결과를 일반적인 우위로 확대하지 않는다.

기존 아모레퍼시픽 실험의 보존율은 Full 109/159(68.6%), Random 89/159(56.0%)이다. 비교기업 LG생활건강은 각각 105/157(66.9%), 77/157(49.0%)이다. 이 수치는 인용 ID 집계이며 아직 독립적인 기사 유용성 평가 결과가 아니다.

## 3. 확인된 제한과 전달 손실

### A. 요약에서 인용하지 않은 기사는 뉴스 분석에 들어가지 않는다

현재 실험은 월별 사건 요약과 그 요약에 인용된 기사만 뉴스 분석에 제공한다. Full은 선정 159건 중 109건, Random은 159건 중 89건이다. 이는 24건 상한 때문이 아니라 요약에서 선택한 기사만 전달하는 정책이다. 요약 모델이 유용한 기사를 놓치면 뉴스 분석에서 해당 기사를 다시 검토할 수 없다.

`News_Agent/analysis_agent.py:221-247`은 이 정책에서 입력 기사 수 전체를 허용하고, 월별 요약의 인용 ID와 원기사 ID가 정확히 일치하는지 확인한다. 여기에 기존 24건 제한을 다시 적용하지 않는다. 입력 메타데이터의 `max_raw_events_per_period: 24`는 이 분기에서 실제 잘라내는 수가 아니다.

### B. 뉴스 분석에서 선택하지 않은 내용은 Strategy에 항상 전달되지는 않는다

뉴스 분석의 긍정 신호·부정 신호·위험·불확실성 배열에는 개수 상한이 없다. 그러나 모든 입력 기사를 개별 분석하거나 사용하지 않은 이유를 기록하는 구조도 아니다. Full 109건에서 분석 주장 26개, Random 89건에서 20개가 생성됐다. 기사 수와 주장 수는 단위가 다르므로 이 차이를 곧바로 누락률로 해석할 수 없다.

`Strategy_Agent/contracts_v2.py:_news_cards`는 생성된 분석 주장을 모두 카드로 보존한다. 실제 `news_preserved_claims`는 Full 26/26, Random 20/20이며 `news_omitted_claims`는 모두 0이다. 같은 근거를 인용했다는 이유로 서로 다른 주장을 합치지도 않는다.

다만 Strategy의 기본 입력은 전체 기사 모음이 아니라 하위 분석 카드다. `context_links.py`가 종합 해석·교차 분석에서 인용된 원자료도 추가하지만, 어디에서도 인용되지 않은 기사까지 전부 추가하지는 않는다. 따라서 뉴스 분석의 선택 자체가 다음 단계에서 볼 수 있는 범위를 정한다.

뉴스 출력 예산은 12,000토큰이다. 실제 출력은 Full 7,121토큰, Random 6,520토큰으로, 이번 결과에서 출력 예산 소진이 잘림 원인이라는 증거는 없다.

### C. 뉴스에 불리하게 읽힐 수 있는 예전 분류값이 Strategy 입력에 남아 있다

`Strategy_Agent/agent.py:1829-1831`은 현재 검증 결과의 claims를 빈 목록으로 둔다. 그런데 `_news_cards`는 검증값이 없을 때 `evidence_use=context_only`를 부여하고, `_news_claim_card`는 `strong`인 경우에만 `primary` 역할을 준다. 따라서 이번 실행의 뉴스 분석 카드는 Full 26개, Random 20개 모두 `evidence_role=reference`가 됐다.

문맥 원자료 카드까지 포함하면 뉴스 카드 Full 50개, Random 46개가 모두 reference다. 반면 재무 카드 중 4개, 시장 카드 중 3개, 비교기업 카드 6개에는 primary가 붙어 있다.

`contracts_v4.py:_neutralize_card`는 `eligibility`, `decision_use`, `allowed_sections`, `event_materiality`를 제거하지만 `evidence_role`과 `machine_blockers`는 제거하지 않는다. 예를 들어 뉴스의 기업 범위가 mixed이면 `news_company_specificity_not_direct`가 남는다.

이 값이 v5에서 기사 사용을 강제로 차단하지는 않는다. 실제로 reference 뉴스도 최종 결정 근거에 선택됐다. 다만 사용 범위를 중립화하려는 설계와 달리, 출처·확정 수준의 사실 정보와 별개인 사전 우선순위 신호가 모델에 노출된다. 이 신호가 실제 선택에 미친 영향은 분리 실험 없이는 단정할 수 없다.

### D. Strategy의 보충 분석은 사건별로 나누기 어렵다

`contracts_v5.py:287`은 `report_insights`를 최대 3개로 제한한다. 같은 파일의 검증은 실적·가격·사건이라는 세 종류의 중복도 금지한다. 따라서 `events_and_execution` 항목은 최대 1개다.

한 항목에서 여러 기사를 인용하거나 전망·위험에 추가 사건을 쓰는 것은 허용된다. 기사 1건 상한은 아니다. 하지만 여러 독립 사건을 하나의 큰 분석 문단에 묶게 하는 구조적 압력이 있다.

프롬프트의 핵심 결정 근거 `통상 1~3개`는 권고이며, 필요한 근거를 수 때문에 제외하지 말라는 지침이 함께 있다. 실제 선택도 Full 5개, Random 6개다. 본문 인용 카드와 문자열 길이에 별도의 작은 상한은 없다. `report_context_cards`의 모델 출력 상한 0은 중복 목록을 모델이 작성하지 않게 하는 것이며, 후처리가 본문·반대 논거·보충 분석·위험에 실제 인용된 카드를 다시 연결한다. 실제 문맥 카드는 각각 17개, 18개다.

### E. Writer는 Strategy의 선택을 되돌릴 수 없고, 전달받은 논거도 생략할 수 있다

`writer_handoff.py:_build_writer_editorial_packet_v5`는 결정 근거와 문맥 근거, 적용되는 한계 근거만 Writer에 전달한다. 실제 Writer 입력은 Full 22개, Random 24개 카드다. Strategy에만 남아 있고 최종 해석에서 선택되지 않은 뉴스는 Writer가 다시 살릴 수 없다. 이는 Writer를 편집 역할로 둔 설계 자체의 경계다.

판단 요약의 핵심 근거와 표는 필수로 연결하지만, 최근 실적·전망의 사용 가능 카드가 모두 필수는 아니다. 반대 논거인 `counterview`의 본문과 카드도 전달되지만, 그 논거의 실질적 보존 여부를 확인하는 계약은 약하다. 인용 가능한 ID가 보존됐다는 사실과 그 의미가 최종 독자 문장에 남았다는 사실은 다르다.

문단 권고는 판단 요약 2개, 최근 실적·가격 3개, 전망 2개, 한계 2개다. 스키마와 텍스트 정리 함수는 이를 넘었다고 자르지 않는다. 이번 두 출력은 요약·실적·전망에서 정확히 2/3/2개를 작성했다. 권고가 간결한 편집을 유도했을 가능성은 있지만, 이것만으로 생략의 원인이라고 확정할 수는 없다.

## 4. 실제 사례

| 사례 | 확인된 전달 경로 | 판단 |
|---|---|---|
| Full의 2025-11-06 3분기 실적 기사 805 | 월별 요약에 존재 → 재무·시장 보조 분석에서 인용 → Strategy 생성 입력의 요약 카드·원기사 카드에 존재 → Strategy 최종 해석 및 Writer 카드에서는 없음 | 수집·전달 단계에서 전부 사라진 것이 아니라 Strategy 선택 단계에서 빠졌다. |
| Random의 2025-11-06 3분기 실적 보도 | 뉴스 분석에 존재 → Strategy 반대 논거에 대상기업 성장·중화권 흑자전환으로 사용 → Writer 입력 본문·카드에도 존재 → 최종 본문과 인용 목록에는 없음 | Writer 편집에서 실질적 근거가 빠졌다. |
| Full의 비교기업 상대 실적 | Strategy 반대 논거와 Writer 입력에 LG생활건강 대비 성장·수익성 비교 존재 → 최종 본문 및 해당 두 카드 인용 없음 | 뉴스에만 국한되지 않은 반대 논거 전달 문제다. |

그룹 실적을 대상기업 실적으로 옮겨 쓰라는 뜻이 아니다. 그룹 수치와 기사에서 확인되는 대상기업의 기여를 구분한 상태에서, 후행 보도가 기존 실적 해석을 어떻게 보완하는지 검토해야 한다. 또한 입력에 있었다는 사실만으로 반드시 보고서에 써야 하는 것은 아니다.

## 5. 최초 검토의 권장 보완 순서

1. Strategy의 모델 입력에서 예전 정책성 역할·차단 라벨을 정리한다. 출처, 기업 범위, 보도·확정 여부, 관측 기간 같은 실제 자료 속성은 유지한다. 기존 카드와 인용 연결이 보존되는지 로컬 테스트로 확인한다.
2. `report_insights`가 독립 사건을 별도로 표현할 수 있도록 건수·유형 중복 제한을 재검토한다. 모든 기사 사용 의무나 사건 수 할당은 넣지 않는다. 뉴스 분석과 Strategy는 기존 판단을 보강하거나 수정하는 근거를 중요도 이유와 함께 선택하도록 한다.
3. Writer가 선택된 판단 이유와 실질적인 대안 논거를 보존하도록 전달 지침을 명확히 한다. 단순 반복 문장은 줄이되 결론을 지탱하는 새로운 사실까지 중복으로 취급하지 않는다. Writer에 전체 기사를 재분석시키거나 별도 유료 검증 에이전트를 추가하지 않는다.
4. 같은 저장 입력으로 두 조건을 동일하게 재확인한다. ID 연결 검사는 코드로, 의미 보존은 표본을 직접 읽어 확인한다. 평가의 공정성을 위해 생성 입력에 남은 선정 점수·순위 같은 검수용 메타데이터도 함께 정리한다. 이후 1절의 독립적인 기사 평가를 진행한다.

이번 점검의 결론은 “더 많은 기사를 무조건 출력하자”가 아니다. 기사 선정 품질, 하위 분석의 판단, Strategy의 근거 선택, Writer의 의미 보존을 구분해 개선해야 한다.

### 변경 사항

- Strategy v5 모델 입력에서 모든 도메인의 `evidence_role`, `machine_blockers`를 제거했다. 기존 카드·출처 기록은 수정하지 않는다. 기업 범위, 보도·확정 여부, 날짜와 재무 연결 상태는 유지한다.
- 뉴스 카드의 원자료·중첩 메타데이터에서 `relevance_rank`, `final_score`, `scores`, `ablation_selection`을 생성 입력에 전달하지 않도록 했다. 저장된 선정 점수·순위는 보존한다. Full과 Random에 같은 처리를 적용한다.
- Strategy `report_insights`의 최대 3개 제한과 동일 유형 중복 금지를 제거했다. 유형 자체와 유효한 인용 ID 검사는 유지한다. 같은 유형이어도 독립 사건은 별도 항목으로 분석·전달할 수 있다.
- 뉴스 분석과 Strategy 지침에 기존 해석을 보강하거나 수정하는 후행 근거를 검토하도록 명시했다. 최신 기사 우선, 긍정·부정 건수 할당, 모든 기사 사용 의무는 넣지 않았다.
- Writer에 대안 논거의 구체적 사실·가정 및 현재 의견을 선택한 이유를 보존하도록 명시했다. 같은 기업·요약 근거·분석 유형을 공유한다는 이유로 독립 사건을 중복으로 처리하지 않도록 했다.
- Writer의 2/3/2 문단 권고와 본문 문단 수·총 글자 수 경고를 제거했다. 사실과 해석의 반복을 줄이라는 지침은 유지했다. 차트 설명 길이의 별도 편집 권고는 이번 본문 변경 대상이 아니다.
- Writer v5 서술형 입력에서도 과거 정책값인 `decision_use`를 제거했다. 비교기업 문맥 카드도 Strategy의 대안 논거를 설명하는 데 사용할 수 있도록 지침을 정리했다. 비교 가능한 지표·기업·기간 범위를 확대하지 않는다.
- 변경 전 생성 결과가 자동 재사용되지 않도록 Strategy 및 Writer 생성 캐시 버전을 갱신했다. 기존 보고서를 삭제하거나 덮어쓰지는 않았다.

## 7. 후속 GPT-5.4 재실행

사용자가 이전 실행과 동일한 GPT-5.4 모델을 선택한 뒤 Full·Random을 각각 재실행했다. 수집·선정·요약 및 변경되지 않은 재무·시장 분석은 재사용했다. 뉴스 4회, 비교 분석 2회, Strategy 2회, Writer 2회가 모두 완료됐다. 추가 사용량은 499,681토큰, 표준 단가 기준 비용은 약 $1.942077이다.

Full의 사건별 전망 설명과 비교기업 논거, Random의 후행 실적 내용 보존은 개선됐다. 그러나 Full은 최신 실적을 여전히 판단 한계 위주로 다루고, 두 조건 모두 주가 상대부진을 시장의 불신으로 해석하는 문제가 남는다. 인용 ID 보존과 의미 보존을 동일시하지 않는다. 이번 한 쌍만으로 Full 우위나 수정의 인과 효과를 확정하지 않는다.

상세 결과: [재실행 정성검토](/home/agent2/ABLATION/experiments/amore_news_usage_revision_gpt54_20260913/결과_정성검토.md). 요약 전 기사 유용성 평가와 보존율 교차 분석은 아직 실행하지 않았다.

## 8. 기사별 날짜와 실적 기간 연결 보완

사용자 승인 후 뉴스 분석 지침에 보도일과 실적 대상 기간, 기업 주체, 누적·단일 기간 및 연결·별도 기준을 구분하도록 추가했다. 여러 분기의 추세 비교는 허용하되 서로 다른 실적을 하나의 발표처럼 합치지 않도록 했다. 같은 실적의 후속 보도를 날짜만 다르다는 이유로 별도 사건으로 늘리는 지침은 넣지 않았다.

Strategy 뉴스 카드의 `cited_sources`에 인용 자료별 정보를 보존한다.

- 기사: `source_type=article`, `source_date`, `title`, `snippet`, 기존 날짜별 진행 내역이 있는 경우 `event_timeline`.
- 월별 요약: `source_type=monthly_news_context`, `period`, `title`, `summary`. 요약 종료일을 기사 보도일로 부여하지 않는다.
- 기사 날짜가 없으면 null로 유지하며 대표 기사 날짜로 채우지 않는다. 날짜나 스니펫이 같더라도 서로 다른 인용 자료를 임의로 합치지 않는다.
- 대표 기사 날짜·기존 출처 기록은 유지한다. Strategy 생성 입력에서는 날짜 없이 나열하던 `representative_excerpts`를 제외해 같은 내용을 이중 입력하지 않는다. 이전 형식의 카드만 있는 경우 기존 목록은 유지한다.
- Strategy 지침에도 대표 날짜를 모든 사건의 날짜로 사용하지 않고, 보도일·요약 기간에서 실적 대상 기간을 추정하지 않도록 명시했다. v5 캐시 버전은 19로 갱신했다.

실제 저장된 새 Full·Random 입력을 로컬에서 재구성해 카드 76/77개와 원본 인용 ID가 그대로 유지됨을 확인했다. Full의 묶인 실적 카드에는 2025-04-30의 1분기 기사와 2025-11-06의 3분기 기사가 각각 날짜·제목·스니펫으로 전달된다. 기존 LLM 주장을 코드로 분리하거나 다시 작성하지는 않았다.

전체 로컬 테스트 212개가 통과했다. 이번 보완 후 유료 재생성은 하지 않았으므로, 뉴스 모델이 실제로 실적 기간을 더 명확하게 구분하는지는 재생성 검증 전이다. 기존 보고서는 변경하지 않았다.
