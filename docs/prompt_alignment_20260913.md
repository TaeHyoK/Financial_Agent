## 순서별 변경

1. **Writer 근거 선택**
   - `required_card_keys_by_component`는 서두의 핵심 논거, 근거 표, 위험 표, 명시적인 자료 범위 설명에 필요한 근거를 유지한다.
   - `available_card_keys_by_component`는 문단에서 사용할 수 있는 Strategy의 선택 근거 전체를 제공한다. 실적·전망 문단은 해당 근거를 모두 인용할 필요가 없다.
   - 모든 뉴스 카드를 전망 절의 필수 인용으로 배정하던 처리를 제거했다. Strategy의 실제 인용 자료와 분석 문장은 입력에 계속 보존한다.
   - 문단의 실제 인용 합집합과 `card_keys` 일치, 허용되지 않은 근거, 필수 근거 누락은 계속 검사한다. 의미를 규칙으로 채점하거나 새 문장을 생성하지 않는다.

2. **재무·시장 작성 순서**
   - 재무: 항목별 분석 → 보조자료 연결 → 종합 판단.
   - 시장: 세부 관측 분석 → 보조자료 연결 → 기간별 해석 → 종합 판단.
   - 스키마의 키 순서와 필수 필드 목록을 함께 정렬했다. 입력 수치, 모델, 생성 설정, 출력 토큰 예산은 유지했다.

3. **Strategy 역할 정합성**
   - system 지시를 자료 분석·대안 비교 후 의견과 선택 이유를 작성하는 역할로 맞췄다. 별도 단계 비교 실험의 같은 system 지시도 맞췄다.
   - 유의미한 대안 해석이 없으면 그 범위를 설명하고 빈 인용 배열을 허용한다. 실제 대안의 사실을 서술하면 근거를 인용하도록 지시한다. 텍스트 의미를 판정하는 검사는 추가하지 않았다.

4. **뉴스 근거별 상태 판단**
   - 개별 기사는 제목·스니펫·진행 내역, 월별 요약은 해당 요약과 이슈를 바탕으로 상태를 판단하도록 했다.
   - 사업상 중요성과 재무 연결 상태의 의미를 정의했다. 재무 연결 미관찰은 효과가 없다는 뜻으로 쓰지 않는다.

5. **월별 요약 분량과 사건 구분**
   - 기존 자료에서 기업·조건별 요약용 기사는 연간 260~261건이었다. 월별 2~4문장·400자, 이슈 3개 안팎은 편집 권고로 유지하되 독립 사건의 사실·시점·진행 상태를 보존하도록 했다.
   - 600자 또는 이슈 3개 초과 시 실패시키던 처리를 제거했다. 빈 요약, 알 수 없는 기간, 기간 누락·중복 검사는 유지했다.
   - 같은 회사·제품의 서로 다른 사건은 병합하지 않도록 했다. 대상기업 혼동과 언론사·주변 기사 설명을 사실로 사용하지 않는 지시도 포함했다. 별도 분류 모델이나 기업명별 예외 규칙은 추가하지 않았다.
   - 기사의 선정 수·가중치·중복 임계값은 바꾸지 않았다. 요약 출력이 늘 수 있으며 실제 분량과 비용은 재생성 후 확인해야 한다.

6. **비교기업의 질적 분석 활용**

   - Writer에는 실제 비교 항목과 대상기업에 대한 의미를 전달한다. 비교기업을 독립적으로 추천·평가하는 절은 만들지 않는다.

7. **Writer 잔여 지시 정리**
   - `one-paper`, 서두 두 문단 이내 강제, 과거 표 구성 설명을 현재 보고서 계약에 맞췄다.
   - 제품 공시 범위는 해당 설명이나 표에서 밝히되 문장마다 같은 문구를 반복하도록 요구하지 않는다. 기존 표의 수치·범위 표시는 유지한다.
   - 가격이 실적을 어떻게 반영했는지 전제하는 질문 대신 실적과 가격에서 각각 판단 가능한 내용을 설명하도록 했다.

- 종합 요약에서 핵심 사업 변화와 실제 반대 근거의 중요도를 비교하고, 기사 건수 대신 사업 연결·발생 여부·지속성에 근거하여 이유를 설명하도록 했다. 반대 근거나 우열을 강제로 만들지 않는다.
- 확인된 긍정·부정 사건과 영향 규모의 불확실성을 분리한다. 금액 미확인으로 사건의 의미를 상쇄하지 않으며, 반대로 영향 규모를 임의로 단정하지 않는다.
- 보조자료의 어떤 관측이 사건 해석을 강화·약화·수정하거나 유지시키는지 `judgment_impact`와 종합 문장에 반영하고 실제 `context_ids`를 연결하도록 했다. 관련 자료가 없으면 연결이나 변화를 만들지 않는다.

기존 지시 일부를 교체하고 종합 작성 기준을 추가했다. 출력 스키마·파서·검증·모델·월별 요약 프롬프트는 변경하지 않았다. 판단 점수, 강제 문구 후처리, 추가 LLM 단계는 도입하지 않았다. Full·Random은 같은 FINAL 실행 경로를 사용하며 one-team도 공통 뉴스 요청을 포함한다. 보조자료 제거 조건에도 같은 분석 지시가 제공된다.

오프라인 테스트 FINAL 160개·ABLATION 86개가 통과했다. 새 테스트는 조건 간 지시 동일성, 원본 입력 불변, 보조자료 전달, 선정 조건 메타데이터 비노출, 종합 출력 필드 유지를 확인한다. 이는 생성 품질 평가가 아니다. 유료 호출과 기존 산출물 재생성은 하지 않았다. 다음 비교는 동일 입력·모델에서 뉴스 분석 프롬프트만 바꿔 수행하며, 요약 단계에서 이미 사라진 내용은 별도로 구분한다.

[OpenAI 공식 프롬프트 지침](https://developers.openai.com/api/docs/guides/model-optimization#write-effective-prompts)의 명확한 출력 목표와 평가를 통한 반복 개선 원칙을 참고했다. 이번 변경의 품질 향상이나 Full 우위는 아직 검증되지 않았다.

## 대상기업·그룹 실적 구분: 프롬프트 우선 보완

월별 요약, 뉴스 분석, Strategy v5, Writer v2에 사실의 기업 주체·연결/별도 기준 보존과 근거 있는 대상기업 기여 서술을 추가했다. 회사명을 비교해 기사를 차단하거나 주장을 수정하는 코드는 추가하지 않았으며 출력 스키마·파서·검증은 유지했다. 특정 기업 예시를 운영 지시에 넣지 않았다. OpenAI Docs 스킬을 사용해 기존 역할별 지시 안에서 변경 범위를 유지했다.
