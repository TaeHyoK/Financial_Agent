# Random 뉴스 분기 변경

## 비교 범위

현재 연간 Random은 DART 기반 기업 식별과 공시 관련성 평가를 함께 제거한다.
순위 알고리즘 하나만의 제거 실험으로 해석하지 않는다.

| 처리 | Full | Random |
| --- | --- | --- |
| 수집 원본·스니펫 확보 | 동일 | 동일 |
| 빈 스니펫 제외 | 적용 | 적용 |
| DART 관계회사 정보에 따른 기업 필터 | 적용 | 미적용 |
| 7일 내 기사 간 의미 중복 병합 | 적용 | 적용 |
| 대표 기사·날짜별 사건 내역 | 기사 묶음 내 유사도 | 같은 방식 |
| 공시 섹션별 임베딩·교차 인코더 | 적용 | 미적용 |
| 요약용 기사 | 주간 최대 3건 | Full의 주간×월간 수량에 맞춰 무작위 추출 |
| 개별 기사 | 월별 최대 2건 | 자체 요약용 기사에서 Full의 월별 수량만큼 무작위 추출 |
| 월간 요약 | 자체 선정 기사로 생성 | 자체 선정 기사로 새로 생성 |
| 요약용 기업 소개·뉴스 분석용 재무/시장 보조자료 | 동일 | 동일 |

기존에는 Full의 기업 필터를 통과하고, 공시 유사도로 대표 기사가 정해진
`news_events_all`에서 Random을 추출했다. 이제 Full 실행 시 별도의
`news_events_prefilter`를 저장하고 연간 Random이 이를 사용한다. 이 후보에는
기업 필터 판정·공시 근거·관련성 점수를 넣지 않는다. 대표 기사는 정규화된
기사 임베딩의 묶음 내 평균 유사도로 정한다. 날짜별 제목도 같은 기준을 사용한다.

실행 규약은 `random_news_v6_without_dart_selection`이다. 이전 Full 후보를
새 규약으로 간주하거나 기사 수가 부족할 때 임의로 채우지 않는다. 주간×월간
수량을 충족하지 못하면 입력 준비 단계에서 확인할 수 있도록 오류를 보고한다.
이는 생성 의견을 제한하는 규칙이 아니라 비교 입력의 동일 조건을 확인하는 절차다.

연간 실행이 기본이며 과거 최종 기사만 교체하던 방식은 `--protocol legacy`로
명시해야 한다. 기존 실험 파일과 결과는 변경하지 않았다.

## 이번 실호출 범위

- 대상기업 아모레퍼시픽, 비교기업 LG생활건강.
- 기준일 2025-11-07, 뉴스 2024-11-07~2025-11-06.
- 기존 전체 스니펫 확보 시도 자료를 사용하며 재수집하지 않는다.
- 시드 20251107, 두 조건 모두 GPT-5.4 mini.
- 기업별·조건별 월간 요약 1회와 뉴스 분석 1회: 총 8회.
- Strategy·Writer·점수 평가 호출은 포함하지 않는다.
- Full의 공시 가중치와 교차 인코더 입력 방향은 이번에 변경하지 않는다.

실행 스크립트와 원본 해시, 실제 요청·응답·사용량은
`/home/agent2/ABLATION/experiments/news_random_prefilter_20260913/`에 저장한다.
요약 출력 상한은 20,000토큰, 뉴스 분석은 기존 12,000토큰을 동일하게 적용하며
상한에 걸리거나 검증에 실패한 응답을 자동 재호출하지 않는다.

## 해석 시 주의점

Random에도 같은 기업 소개와 분석용 보조자료가 제공된다. 따라서 DART를 전혀
보지 않는 에이전트가 아니라, **뉴스 선정에서 DART를 쓰지 않는 조건**이다.
뉴스 분석을 수행하는 LLM은 입력 중 덜 중요한 기사를 판단에서 제외할 수 있다.
이를 억지로 활용하도록 프롬프트를 다르게 주지 않는다.

저장된 스니펫의 인코딩 오류·기사 주변 목록 혼입 가능성은 이번 분기 변경만으로
해결되지 않는다. 동일한 수집 품질 정책을 공유한다고 해서 모든 기사 품질이
보장되는 것은 아니다. 한 기업·한 시드의 결과로 전체 성능 우위를 주장하지 않는다.
